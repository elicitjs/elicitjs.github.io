Getting started

Install ElicitJS, build a chart, make it editable, and read the answer back. Every example below is live — edit the code and the chart re-renders.

Install

ElicitJS is ESM-only and needs a bundler (Vite, webpack, Next, …) or an import map. d3 v7 is a peer dependency: npm 7+ and pnpm 8+ install it for you; on Yarn add it explicitly.

npm install elicitjs

import { Elicit, plot, edit, constraints } from "elicitjs";

Types ship with the package, so TypeScript works with no @types install. There is also a prebuilt single-file bundle at elicitjs/dist if you would rather not bundle the source, and a CDN path for a plain HTML page:

<script type="importmap">
  {
    "imports": {
      "d3": "https://cdn.jsdelivr.net/npm/d3@7/+esm",
      "elicitjs": "https://cdn.jsdelivr.net/npm/elicitjs@alpha/dist/elicit.js"
    }
  }
</script>
<script type="module">
  import { Elicit, plot, edit } from "elicitjs";
</script>

A chart is a spec

Elicit(spec) takes one object and returns a DOM element you append. A spec has three required parts and one optional one:

  • data — the dataset. A chart elicits exactly one; every mark is a view over those rows.
  • schema — what each field is: its measurement type and its domain. Scales are derived from this, so no mark declares one.
  • marks — how the rows are drawn.
  • constraints — optional invariants the data must satisfy.

Start with a chart that only displays. This is a complete, valid spec:

The channels map is where a mark names its columns. x: { field: "cat" } says the x position encodes cat; because the schema declares cat as categorical and a bar needs an interval, that resolves to a band scale. You never write the scale down.

A static bar chart

data + schema + marks. Nothing here is editable yet — it is an ordinary chart.

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 40 },
  // The DATA — one dataset, and every mark is a view over it.
  data: [
    { cat: "A", n: 30 }, { cat: "B", n: 55 },
    { cat: "C", n: 22 }, { cat: "D", n: 44 },
  ],
  // The SCHEMA — what each field IS. Every scale is derived from this.
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 60] },
  },
  // The MARKS — how the rows are drawn.
  marks: [
    barY({
      fill: "#4f46e5",
      channels: { x: { field: "cat" }, y: { field: "n" } },
    }),
  ],
}))

Make it editable

An edit is the inverse of encoding. A channel encodes data → pixels through a scale; an edit attached to that channel maps a gesture → data back through the same scale. So making a chart elicitable is one added word on the channel you want written:

This is the rule that makes the rest of the library predictable: a mark is inert until an edit names the column it writes. No mark interacts by default, and which column a gesture writes is always visible in the spec.

move() is one of about 26 universal edits. Others let you create and delete rows, draw a path, rotate a needle, pick a category from a legend, or rewrite a scale's domain — see Editing for the vocabulary, or the API index for the whole list.

The same chart, now editable

`edit: move()` on the y channel. Drag a bar — the drag inverts the y scale and writes `n`.

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 40 },
  data: [
    { cat: "A", n: 30 }, { cat: "B", n: 55 },
    { cat: "C", n: 22 }, { cat: "D", n: 44 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 60] },
  },
  marks: [
    barY({
      fill: "#4f46e5",
      channels: {
        x: { field: "cat" },
        // One added word. `move()` inverts the y scale, so a drag writes `n`.
        y: { field: "n", edit: move() },
      },
    }),
  ],
}))
Try: Drag any bar up or down.

Read the answer back

The elicited data is the point. There are two ways to get it:

  • onChange(data) — fires after every committed edit, with the whole dataset.
  • chart.getData() — read it on demand, whenever you need it.

The element Elicit returns also carries getSchema(), setData(), on("change" | "stage", cb), undo(), redo() and destroy(). Call destroy() when unmounting in a framework — it releases the resize observer and pointer handlers.

Reading the elicited data

onChange writes the current values under the chart. Drag a bar and watch it update.

const chart = Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 40 },
  data: [
    { cat: "A", n: 30 }, { cat: "B", n: 55 },
    { cat: "C", n: 22 }, { cat: "D", n: 44 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 60] },
  },
  // Fires after every committed edit, with the whole dataset.
  onChange: (data) => {
    readout.textContent = data.map((d) => `${d.cat}: ${Math.round(d.n)}`).join("   ");
  },
  marks: [
    barY({
      fill: "#4f46e5",
      channels: { x: { field: "cat" }, y: { field: "n", edit: move() } },
    }),
  ],
});

const readout = document.createElement("pre");
readout.style.cssText = "font-size:12px;margin:8px 0 0;color:#55606c";
readout.textContent = chart.getData().map((d) => `${d.cat}: ${d.n}`).join("   ");

mount(chart);
mount(readout);
Try: Drag a bar — the numbers below follow.

Constrain what can be said

Elicitation usually has rules: shares sum to 100, a lower bound cannot cross an upper one, no value goes negative. Those are facts about the data, not about any one mark, so they live in one place — spec.constraints — and they hold for every edit from every mark.

A constraint can gate a proposal (reject it) or repair it (return corrected rows). See Constraints for the full set.

Four bars that always sum to 100

clamp keeps values non-negative; maintainSum redistributes so the total holds.

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 40 },
  data: [
    { cat: "A", n: 25 }, { cat: "B", n: 25 },
    { cat: "C", n: 25 }, { cat: "D", n: 25 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 100] },
  },
  // A rule about the DATA, not about any one mark. It holds for every edit.
  constraints: [clamp({ min: 0 }), maintainSum({ total: 100 })],
  marks: [
    barY({
      fill: "#4f46e5",
      channels: { x: { field: "cat" }, y: { field: "n", edit: move() } },
    }),
  ],
}))
Try: Drag a bar — the others compensate.

Or skip the spec entirely

Common survey instruments are one call each. Each returns a plain spec you pass to Elicit, so you can start from a widget and then edit its spec when you need something it does not do.

import { Elicit, widgets } from "elicitjs";

document.body.appendChild(Elicit(widgets.likert({
  question: "How confident are you?",
  scale: ["Not at all", "Slightly", "Moderately", "Very", "Extremely"],
})));

likert, slider, matrix, ranking, allocation, interval, thermometer, histogram and more — see Widgets.
