Getting started

Install ElicitJS, build a chart with Elicit(spec), make it editable by putting an edit on a channel, and read the answer back through onChange.

Install

ElicitJS is ESM-only. Use it with a bundler (Vite, webpack, Next) or an import map.

npm install elicitjs

d3 v7 is a peer dependency. npm 7+ and pnpm 8+ install it for you; on Yarn, add it yourself with yarn add elicitjs d3.

import { Elicit, plot, edit, constraints } from "elicitjs";

Types ship with the package, so TypeScript needs no separate @types install. elicitjs/dist is a prebuilt single-file bundle if you would rather not bundle the source.

For a plain HTML page, map both names in an import map:

<script type="importmap">
  {
    "imports": {
      "d3": "https://cdn.jsdelivr.net/npm/d3@7/+esm",
      "elicitjs": "https://cdn.jsdelivr.net/npm/elicitjs@alpha/dist/elicit.js"
    }
  }
</script>
<script type="module">
  import { Elicit, plot, edit } from "elicitjs";
</script>

A chart is a spec

Elicit(spec) takes one object and returns a DOM element you append. A spec has three required keys:

  • data — the dataset. A chart elicits exactly one, and every mark is a view over those rows.
  • schema — each field's type and domain. Scales are derived from this, so no mark declares one.
  • marks — how the rows are drawn.

A mark names its columns in channels. x: { field: "cat" } encodes cat on the x position. The schema declares cat as categorical and a bar needs an interval, so that resolves to a band scale. You never write the scale down.

A static bar chart

A complete spec: data, schema and one mark. Nothing here is editable yet.

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 40 },
  // The DATA — one dataset, and every mark is a view over it.
  data: [
    { cat: "A", n: 30 }, { cat: "B", n: 55 },
    { cat: "C", n: 22 }, { cat: "D", n: 44 },
  ],
  // The SCHEMA — what each field IS. Every scale is derived from this.
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 60] },
  },
  // The MARKS — how the rows are drawn.
  marks: [
    barY({
      fill: "#4f46e5",
      channels: { x: { field: "cat" }, y: { field: "n" } },
    }),
  ],
}))

Make it editable

An edit is the inverse of encoding. A channel encodes data to pixels through a scale. An edit on that channel maps a gesture back through the same scale, and writes the column the channel names.

A mark is inert until an edit names the column it writes. No mark interacts by default, so the spec always says which column a gesture changes.

move() is one of the universal edits, which work on any mark. Others create and delete rows, draw a path, turn a needle, pick a category from a legend, or rewrite a scale's domain. See Editing for the vocabulary, or the API index for every name.

The same chart, now editable

`edit: move()` on the y channel. Dragging a bar inverts the y scale and writes `n`.

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 40 },
  data: [
    { cat: "A", n: 30 }, { cat: "B", n: 55 },
    { cat: "C", n: 22 }, { cat: "D", n: 44 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 60] },
  },
  marks: [
    barY({
      fill: "#4f46e5",
      channels: {
        x: { field: "cat" },
        // One added word. `move()` inverts the y scale, so a drag writes `n`.
        y: { field: "n", edit: move() },
      },
    }),
  ],
}))
Try: Drag any bar up or down.

Read the answer back

Two ways to get the elicited data:

  • onChange(data) fires after every committed edit, with the whole dataset.
  • chart.getData() returns it on demand.

The returned element also carries getSchema(), setData(), on("change" | "stage", cb), undo(), redo() and destroy(). Call destroy() when unmounting in a framework to release the resize observer and pointer handlers.

Reading the elicited data

`onChange` writes the current values under the chart.

const chart = Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 40 },
  data: [
    { cat: "A", n: 30 }, { cat: "B", n: 55 },
    { cat: "C", n: 22 }, { cat: "D", n: 44 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 60] },
  },
  // Fires after every committed edit, with the whole dataset.
  onChange: (data) => {
    readout.textContent = data.map((d) => `${d.cat}: ${Math.round(d.n)}`).join("   ");
  },
  marks: [
    barY({
      fill: "#4f46e5",
      channels: { x: { field: "cat" }, y: { field: "n", edit: move() } },
    }),
  ],
});

const readout = document.createElement("pre");
readout.style.cssText = "font-size:12px;margin:8px 0 0;color:#55606c";
readout.textContent = chart.getData().map((d) => `${d.cat}: ${d.n}`).join("   ");

mount(chart);
mount(readout);
Try: Drag a bar — the numbers below follow.

Constrain what can be said

A constraint is a rule over the dataset. It applies to every edit and every mark, so declare it once in constraints: [...] on the spec.

A constraint can reject a proposed change, or repair it by returning corrected rows. See Constraints for the full set.

Four bars that always sum to 100

`clamp` keeps values non-negative. `maintainSum` redistributes so the total holds.

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 40 },
  data: [
    { cat: "A", n: 25 }, { cat: "B", n: 25 },
    { cat: "C", n: 25 }, { cat: "D", n: 25 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 100] },
  },
  // A rule about the DATA, not about any one mark. It holds for every edit.
  constraints: [clamp({ min: 0 }), maintainSum({ total: 100 })],
  marks: [
    barY({
      fill: "#4f46e5",
      channels: { x: { field: "cat" }, y: { field: "n", edit: move() } },
    }),
  ],
}))
Try: Drag a bar — the others compensate.

Widgets

Common survey instruments are one call each. Each returns a spec you pass to Elicit, so you can start from a widget and edit its spec when you need something it does not do.

import { Elicit, widgets } from "elicitjs";

document.body.appendChild(Elicit(widgets.likert({
  question: "How confident are you?",
  scale: ["Not at all", "Slightly", "Moderately", "Very", "Extremely"],
})));

likert, slider, matrix, ranking, allocation, interval, thermometer and histogram are documented on Widgets.
