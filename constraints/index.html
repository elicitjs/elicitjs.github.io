Constraints

A constraint is a rule over the dataset. It applies to every edit and every mark, regardless of which one declared it. It can reject a proposed change, or repair it by returning corrected rows — a repair shows up everywhere on the next render, since every mark reads the same rows. Declare it in constraints: [...] on the Elicit spec — the one place it goes, because it is a rule about the data, not about any one mark. clamp bounds a field, maintainSum fixes a total, count caps the size, and unique forbids duplicate keys. Three more constrain shape: ordering keeps a row's fields in order (lo ≤ mean ≤ hi), monotonic keeps a cumulative curve from dipping, and spacing keeps neighbours from colliding.

API reference

Built-in constraints

Import from elicit.constraints and pass on the Elicit spec’s constraints: [...]. That is the only place they go: a constraint gates every edit from every mark, so writing one inside a mark would say something the engine does not mean. All are pure data invariants — they run on every commit and never see pixels.

Returns / emits

Each returns a Constraint — a reducer the engine runs on the proposed dataset after every edit.

constraints.custom(apply, meta?)

Author your own. One word for “author your own X” in every grammar namespace — cf. edit.custom and guides.custom. (authoring.defineConstraint is the same function, under the name a mark author reaches for.) Every constraint is a descriptor — { type, field?, options, apply } — and field left out means the column the dispatching edit writes, so a one-column instrument names nothing twice. The rule gets a pure-data context and returns the shape that’s natural.

constraints.custom(({ data, oldData, activeIndex, active, field, fields, value, domain, table, tables }) => result, meta?) → Constraint

A Constraint. The ctx.active is the datum the gesture touched; domain is that field’s declared data range.

maintainSum — a total held at 100

The sum rule is a dataset invariant, so it holds for every edit from every mark. Bars give way to keep the total at 100; guide: true draws the live bound.

Bars that compensate

maintainSum bounds the touched bar so the total stays 100; a rule guide marks the even split.

mount(Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  guides: [ guides.rule({ y: 25, label: "even split (25)" }) ],
  data: ["A", "B", "C", "D"].map((c) => ({ x: c, y: 25 })),
  // Invariants on the DATA — they gate every edit, from every mark.
  constraints: [
    clamp({ field: "y", min: 0 }),
    maintainSum({ field: "y", total: 100 }),
  ],
  schema: {
    x: { type: "categorical", domain: ["A", "B", "C", "D"] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    bar({
      fill: "#6366f1",
      channels: {
        x: { field: "x" },
        y: { field: "y", edit: move({ guide: true }) },
      },
    }),
  ],
}))
Try: Drag any bar — the others compensate.

clamp — bound a field

clamp holds a field inside [min, max] — the field you name, or, with none named, whichever column the edit is writing. Pair it with a nearest pick and a self-drawn guide to make the bounds visible while dragging.

Clamped drag with a guide

The y edit is clamped to 0–90; guide: true draws the bounds and the snap ring.

mount(Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: [
    { x: "A", y: 20 }, { x: "B", y: 45 },
    { x: "C", y: 30 }, { x: "D", y: 60 },
  ],
  constraints: [ clamp({ field: "y", min: 0, max: 90 }) ],
  schema: {
    x: { type: "categorical", domain: ["A", "B", "C", "D"] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    bar({
      fill: "#2563eb",
      channels: {
        x: { field: "x" },
        y: { field: "y",
             edit: move({ pick: "nearest", threshold: 40, guide: true }) },
      },
    }),
  ],
}))
Try: Drag from anywhere in a column (clamped to 0–90).

unique — one per key

unique forbids two rows with the same key. A single field guards one axis; an array is a composite key — at most one mark per cell, for both create and move.

One bar per category

create mints wherever you click, but unique({ field: "x" }) rejects a filled slot.

mount(Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: [{ x: "A", y: 40 }, { x: "C", y: 60 }],
  constraints: [ unique({ field: "x", max: 1 }) ],
  schema: {
    x: { type: "categorical", domain: ["A", "B", "C", "D"] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    bar({
      fill: "#0d9488",
      channels: {
        x: { field: "x" },
        y: { field: "y", edit: move() },
      },
      edits: [ create({ defaults: { y: 20 } }) ],
    }),
  ],
}))
Try: Click an empty column to fill it · a filled column rejects.

Composite key — a band × band grid

unique({ field: ["x","y"] }) allows at most one mark per (x, y) cell.

mount(Elicit({
  width: 400, height: 320,
  data: [
    { x: "A", y: "Low", group: "alpha" },
    { x: "B", y: "Mid", group: "beta" },
    { x: "C", y: "High", group: "gamma" },
  ],
  constraints: [ unique({ field: ["x", "y"], max: 1 }) ],
  schema: {
    x:     { type: "categorical", domain: ["A", "B", "C"] },
    y:     { type: "ordinal",     domain: ["Low", "Mid", "High"] },
    group: { type: "ordinal", domain: ["alpha", "beta", "gamma"] },
  },
  marks: [
    point({
      size: 12,
      channels: {
        x: { field: "x" },
        y: { field: "y" },
        fill: { field: "group" },
      },
      edits: [
        move({ channels: ["x", "y"] }),
        create({ defaults: { group: "alpha" } }),
        remove({ when: when.alt }),
      ],
    }),
  ],
}))
Try: Drag to another cell · Click an empty cell to add · Alt+click to delete.

ordering — fields of a row, in order

An error bar's caps and mean are separate marks over separate fields of one row. Without this rule, dragging the low cap above the high one draws the glyph inside-out and reverses what the interval means. ordering holds across all three marks, whichever handle you drag.

An interval that can’t invert

ordering({ field: ["lo", "mean", "hi"] }) — one rule across three marks.

mount(Elicit({
  width: 320, height: 260,
  margins: { top: 20, right: 20, bottom: 30, left: 44 },
  axes: { y: {}, x: false },
  schema: {
    q:    { type: "categorical",  domain: ["2027 GDP"] },
    lo:   { type: "quantitative", domain: [0, 10] },
    mean: { type: "quantitative", domain: [0, 10] },
    hi:   { type: "quantitative", domain: [0, 10] },
  },
  data: [{ q: "2027 GDP", lo: 2, mean: 4, hi: 6 }],
  // Declared ONCE, on the dataset — so it holds whichever of the three
  // handles you grab, and would hold for a create or a keyboard nudge too.
  constraints: [ ordering({ field: ["lo", "mean", "hi"] }) ],
  marks: [
    // An interval glyph is three marks over three FIELDS of one row.
    ruleY({ channels: { x: { field: "q" },
                        y1: { field: "lo" }, y2: { field: "hi" } },
            stroke: "#94a3b8", strokeWidth: 2 }),
    tickY({ channels: { x: { field: "q" }, y: { field: "lo",
              edit: move() } }, stroke: "#64748b" }),
    tickY({ channels: { x: { field: "q" }, y: { field: "hi",
              edit: move() } }, stroke: "#64748b" }),
    point({ size: 7, fill: "#2563eb",
            channels: { x: { field: "q" }, y: { field: "mean",
              edit: move() } } }),
  ],
}))
Try: Drag the low cap up past the mean: the mean and the high cap are carried along rather than the cap sticking. The handle you grabbed is the one you meant.

monotonic — a curve that can’t go back on itself

A CDF, a survival function, a dose-response curve — none of these can dip, but a you-draw-it stroke doesn't know that and will draw one anyway. monotonic repairs the drag instead of rejecting it: it pushes the rows the moved point would have crossed, rather than freezing the curve against its own history.

A curve that can only rise

monotonic({ field: "p", along: "year" }) — the rule behind every CDF.

mount(Elicit({
  width: 420, height: 260,
  margins: { top: 16, right: 16, bottom: 32, left: 42 },
  schema: {
    year: { type: "quantitative", domain: [2025, 2032] },
    p:    { type: "quantitative", domain: [0, 1] },
  },
  data: [
    { year: 2025, p: 0.05 }, { year: 2026, p: 0.12 },
    { year: 2027, p: 0.20 }, { year: 2028, p: 0.34 },
    { year: 2029, p: 0.45 }, { year: 2030, p: 0.60 },
    { year: 2031, p: 0.72 }, { year: 2032, p: 0.80 },
  ],
  // "By when will it have happened?" — a cumulative probability cannot dip,
  // because a dip is negative probability mass. The gesture has no idea; the
  // dataset invariant does.
  constraints: [
    monotonic({ field: "p", along: "year" }),
    clamp({ min: 0, max: 1, field: "p" }),
  ],
  marks: [
    lineY({
      stroke: "#2563eb", handleSize: 5,
      channels: { x: { field: "year" },
                  y: { field: "p", edit: move() } },
    }),
  ],
}))
Try: Drag a middle point up hard: the points to its right rise to meet it, because “it reaches this level by here” says something about later years too. Drag it down and the left-hand points give way instead.

spacing — neighbours that keep their distance

For elicitations where "distinct" is part of the claim: thresholds of a scale, breakpoints of a piecewise curve, tiers of a rubric. Two coincident points are occasionally a genuine belief, but more often a slip of the hand — and once overlapped, the topmost point takes every subsequent grab and the two can't be separated again.

Thresholds that stay apart

spacing({ field: "at", min: 8 }) — no two boundaries closer than 8 points.

mount(Elicit({
  width: 420, height: 170,
  margins: { top: 20, right: 24, bottom: 34, left: 24 },
  axes: { x: {}, y: false },
  schema: {
    grade: { type: "categorical",  domain: ["D", "C", "B", "A"] },
    at:    { type: "quantitative", domain: [0, 100] },
  },
  data: [
    { grade: "D", at: 50 }, { grade: "C", at: 65 },
    { grade: "B", at: 78 }, { grade: "A", at: 90 },
  ],
  // Where do the grade boundaries go? Two coincident thresholds are almost
  // always a slip of the hand — they read as one, and the top one then takes
  // every later grab, so they can never be separated again.
  // `min` is in DATA units: a constraint never sees the scale, and a rule that
  // changed meaning when the chart was resized wouldn't be an invariant.
  constraints: [
    spacing({ field: "at", min: 8 }),
    clamp({ min: 0, max: 100, field: "at" }),
  ],
  marks: [
    tickX({
      strokeWidth: 2, stroke: "#2563eb",
      channels: { x: { field: "at", edit: move() } },
    }),
    text({
      dy: -14, fontSize: 11, fill: "#64748b",
      channels: { x: { field: "at" }, text: { field: "grade" } },
    }),
  ],
}))
Try: Drag one threshold into its neighbour: it pushes rather than overlaps, and the shove carries down the line. Pushing apart preserves the order, so this field needs no ordering as well.
