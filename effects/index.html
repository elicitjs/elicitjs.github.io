Interaction effects

An effect is transient feedback for the state of an interaction: hovered, selected, grabbed. Set them in effects: \{ ... \} on the Elicit spec. Effects never write a mark's paint channels, so they can't clobber a data-driven fill or stroke. For the rules a gesture obeys — a clamp's bounds, a pick's reach — see Guides.

API reference

effects (on Elicit)

The interaction-state feedback layer, passed as effects on Elicit. Keyed by state; partial sub-objects merge over the defaults, so you override just the part you care about. Rules (constraint bounds, a pick’s reach, a handle’s track) are not effects — they live on the edit’s guide.

effects: { hovered, selected, grabbed }
Options
OptionTypeDefaultDescription
hoveredfalse | objectoutlineThe pointer is over this mark, or a proximity pick resolved it. Both routes draw the same thing. false disables it.
selectedfalse | objectoutlineThe mark is in the chart's selection (edit.select / el.select). Outranks hovered.
grabbedfalse | string | objectbrightness(0.82)A drag on this mark is in flight. A string is shorthand for { filter }.
<state>.filterstring—A CSS filter on the mark's own element — the one effect that survives a mid-drag re-render untouched.
<state>.opacity · fill · stroke · strokeWidth · cursorany—Element effects, applied as CSS properties so they override the mark's paint while set and are removed cleanly on exit.
<state>.outlinefalse | { color, width, pad, dash, opacity }accentAn outline overlay traced around the mark, above every other layer. Handles every node type — circle, rect, line, path and text.
Returns / emits

Effects draw either as CSS properties on the element or as overlay nodes — never as the fill/stroke attributes a mark’s channels write — so they can’t clobber data-driven style.

The three states

effects is keyed by state, and every state takes the same options.

hovered applies when the pointer is over the mark, or when a proximity pick has resolved it. Both routes draw the same thing, whether you point at a mark or a pick: "nearest" edit picks it as the closest.

selected applies when the mark is in the chart's selection.

grabbed applies while a drag on it is in flight. Pass a string as shorthand for \{ filter \}.

Set a state to false to switch it off.

Hover on an editable mark

hovered applies to every editable mark. You don't opt in, and it doesn't need a pick — point at a draggable bar and it responds before you press.

A plain draggable bar

A single move() on y. Nothing in the spec asks for hover feedback.

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 14, right: 14, bottom: 28, left: 34 },
  data: [
    { cat: "A", n: 62 }, { cat: "B", n: 38 },
    { cat: "C", n: 81 }, { cat: "D", n: 24 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    bar({
      channels: {
        x: { field: "cat" },
        // A plain direct-pick edit: you point straight at the bar. `hovered`
        // applies to it like any other editable mark.
        y: { field: "n", edit: move() },
      },
    }),
  ],
}))
Try: Move across the bars without pressing, then drag one.

The two mechanisms

Each state paints in one of two ways, and can use both at once.

Element props restyle the mark itself: filter, opacity, fill, stroke, strokeWidth, cursor. They apply as CSS properties, which override a mark's own paint while the state holds and are removed when it ends. Your data-driven fill and stroke are never written. (filter and cursor are SVG-only — a canvas has no element to hover and no per-shape filter. Everything else paints in both renderers.)

outline draws an overlay around the mark, above every other layer. It takes color, width, pad, dash and opacity, and traces whatever shape the mark is: a ring on a circle, a padded ellipse on an ellipse, an inflated box on a rect or tick, the path itself on an arc slice or polygon, a ring at the anchor on a label.

Restyling is the mark's own node, so it follows the mark wherever the mark goes. An outline is a separate node, and it copies the mark's rotation to keep up: spin a mark with an angle channel and its outline turns with it rather than staying square to the axes. Proximity picking measures that same rotated geometry, so what lights up and what a drag actually grabs are always the same mark.

Element props, and outline

Left restyles the dot; right leaves it alone and rings it. Both keep the fill the data gives it.

// Two ways to paint a state, both available on every state.
//
//   element props  filter / opacity / fill / stroke / strokeWidth / cursor —
//                  restyle the mark itself, without writing its own paint.
//   outline        an overlay traced around the mark, above every layer.
//
// Left uses element props, right an outline. The dots keep the fill their `group`
// field gives them in both.
const rows = [
  { x: 22, y: 34, group: "a" },
  { x: 50, y: 66, group: "b" },
  { x: 78, y: 40, group: "a" },
];
const schema = {
  x:     { type: "quantitative", domain: [0, 100] },
  y:     { type: "quantitative", domain: [0, 100] },
  group: { type: "categorical", domain: ["a", "b"] },
};
const dots = () => point({
  size: 11, stroke: "#ffffff", strokeWidth: 2,
  channels: {
    x:    { field: "x", edit: move() },
    y:    { field: "y", edit: move() },
    fill: { field: "group" },
  },
});

// Element props: the dot brightens and thickens. No overlay.
mount(Elicit({
  width: 300, height: 220,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: rows, schema,
  effects: {
    hovered:  { filter: "brightness(1.25)", strokeWidth: 4 },
    grabbed:  { filter: "brightness(0.8)" },
    selected: false,
  },
  marks: [ dots() ],
}));

// Outline: the dot is untouched, and a ring is drawn around it.
mount(Elicit({
  width: 300, height: 220,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: rows, schema,
  effects: {
    hovered:  { outline: { color: "#0f172a", width: 2, pad: 7, dash: "3 3", opacity: 0.9 } },
    selected: false,
  },
  marks: [ dots() ],
}));
Try: Hover both charts. The dots' own colours never change.

Hovered and selected together

selected outranks hovered, so a selected mark is never also drawn as hovered. Give the two different weights: hovered says which mark a gesture would take, selected says which one you picked.

Selection is pipeline state, not a data column — edit.select writes no selected field. See Editing a selected item.

A light hover, a firm selection

Alt-click selects, so a plain click still drags. Hover stays light; the selection holds.

mount(Elicit({
  width: 380, height: 250,
  margins: { top: 14, right: 14, bottom: 28, left: 34 },
  data: [
    { cat: "A", n: 62 }, { cat: "B", n: 38 },
    { cat: "C", n: 81 }, { cat: "D", n: 24 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 100] },
  },
  // Different weights: `hovered` says which bar a gesture would take, `selected`
  // says which one you picked. `selected` outranks `hovered`.
  effects: {
    hovered:  { outline: { color: "#94a3b8", width: 2,   pad: 3, opacity: 0.9 } },
    selected: { outline: { color: "#0f766e", width: 3,   pad: 3, opacity: 1 } },
    grabbed:  { filter: "brightness(0.85)" },
  },
  marks: [
    bar({
      channels: { x: { field: "cat" }, y: { field: "n", edit: move() } },
      // Selection is pipeline state, not a data column: nothing here writes a
      // `selected` field. Alt-click selects, so a plain click still drags.
      edits: [ select({ when: when.alt }) ],
    }),
  ],
}))
Try: Alt-click a bar to select it, hover the others, drag any.

Switching a state off

false disables a state. Turn one off where the mark already reads clearly enough on its own, such as a dense grid where an outline per cell adds noise.

Feedback only on drag

hovered: false and selected: false; only the drag reads back.

// `false` disables a state. Here hover and selection are off, so only the drag
// reads back.
mount(Elicit({
  width: 380, height: 240,
  margins: { top: 14, right: 14, bottom: 28, left: 34 },
  data: [
    { cat: "A", n: 62 }, { cat: "B", n: 38 },
    { cat: "C", n: 81 }, { cat: "D", n: 24 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 100] },
  },
  effects: {
    hovered:  false,
    selected: false,
    grabbed:  { filter: "brightness(0.78) saturate(1.4)" },
  },
  marks: [
    bar({ channels: { x: { field: "cat" }, y: { field: "n", edit: move() } } }),
  ],
}))
Try: Hover a bar, then drag it.

Hover and proximity, one signal

A pick: "nearest" drag draws two things. The ring is the pick's catchment, a guide on the edit. The outline on the resolved dot is the hovered effect — the same one you get by pointing straight at a mark.

Proximity select

Move near a dot to select it; drag from empty space to grab the nearest.

mount(Elicit({
  width: 340, height: 240,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: [{ x: 25, y: 35 }, { x: 55, y: 68 }, { x: 78, y: 30 }],
  schema: {
    x: { type: "quantitative", domain: [0, 100] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    point({
      fill: "#ffffff", stroke: "#334155", strokeWidth: 2,
      size: 10,
      channels: {
        x: { field: "x" },
        y: { field: "y" },
      },
      edits: [ move({ channels: ["x", "y"], pick: "nearest", threshold: 45, guide: true }) ],
    }),
  ],
}))
Try: Move near a dot to select it · Drag from empty space to grab the nearest.

Customized effects

The same edit, restyled. The states go in effects; the ring goes in the edit's guide: \{ catchment \}, since it describes the pick rather than the mark's state. The dots keep the stroke you set throughout.

Restyled feedback

Indigo ring, thicker outline, softer grab — paint channels untouched.

mount(Elicit({
  width: 340, height: 240,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  // EFFECTS are interaction STATE. Each state takes the same vocabulary:
  // element props (filter / opacity / fill / stroke / strokeWidth / cursor) that
  // ride as CSS over the mark's own paint, plus an `outline` overlay.
  effects: {
    hovered:  { outline: { color: "#818cf8", width: 2, pad: 8, opacity: 0.7 } },
    selected: { outline: { color: "#4f46e5", width: 4, pad: 8, opacity: 1 } },
    grabbed:  { filter: "brightness(1.08)" },
  },
  data: [{ x: 25, y: 35 }, { x: 55, y: 68 }, { x: 78, y: 30 }],
  schema: {
    x: { type: "quantitative", domain: [0, 100] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    point({
      fill: "#ffffff", stroke: "#334155", strokeWidth: 2,
      size: 10,
      channels: {
        x: { field: "x" },
        y: { field: "y" },
      },
      // The snap ring is a GUIDE — it shows the pick's reach, a rule about what a
      // gesture will grab — so it is styled on the edit, not in `effects`.
      edits: [ move({
        channels: ["x", "y"], pick: "nearest", threshold: 45,
        guide: { catchment: { color: "#4f46e5", dash: "1 3", width: 1.5, opacity: 0.5 } },
      }) ],
    }),
  ],
}))
Try: Move / drag — indigo ring, thicker outline, softer grab.
