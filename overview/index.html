Overview

ElicitJS builds charts people answer with — drag a bar, place a point — and you get structured data back. A chart is a declarative Elicit(spec): one schema, one dataset, and a list of marks. Every example on these pages runs the exact code beside it. This page is the wiring; Core concepts is the mental model.

API reference

Elicit(spec)

The entry point (elicit.Elicit). Returns a DOM element you append. A chart is one schema, one dataset, and a list of marks — plus optional constraints, axes, and guides.

Elicit({ schema, data?, marks, width?, height?, … }) → ElicitElement

OptionTypeDefaultDescription

marksMark[][]The marks — bar(...), point(...), composite(...), … drawn in array order (later marks on top). Auto-axes and edit guides keep their own layers behind / in front of marks.

Returns / emits

An ElicitElement (a positioned container) carrying the methods below. The engine deep-copies data and owns it; marks re-derive from the committed rows on every render.

The element Elicit returns

An ordinary DOM node — append it where you like — with the chart’s API hung off it. There is no separate handle object to keep in sync, and no global registry: everything a caller needs is on the element.

Options
OptionTypeDefaultDescription
getData()→ Datum[]—A deep copy of the committed dataset — the elicited answer. Copy, because handing out the live rows would let a caller mutate past every constraint the chart just enforced.
getSchema()→ Schema—A deep copy of the engine-owned schema, including any domain an editable axis reshaped. Your original spec.schema is never mutated.
setData(data)void—Replace the dataset and re-render. Bypasses constraints — it is a trusted seed or reset, not an edit — and clears the undo history for the same reason.
on(type, cb)→ unsubscribe—change fires on every committed edit with the new data; stage fires when a stage advances. Returns a function that removes the listener.
undo() / redo()→ boolean—Step one gesture, and report whether they moved. See History & keyboard.
getStage() / setStage(i) / nextStage() / getStageLabel()→ number | string | void—Read and drive a multi-step elicitation from outside. See Stages.
select(i) / selectWhere / toggleSelection / selectAll / clearSelectionvoid—Set which rows the chart considers selected, by index or by a field match. See Selection.
getSelection() / getSelectionAll()→ number | number[]—The selected row, and every selected row when the selection is multiple.
control(name, index?)→ EditControl—Drive a named edit from outside the chart (a slider, a picker). Same dispatch as the pointer — constraints, undo, and change all run. See External controls.
emit(event)void—Low-level: inject a renderer-shaped gesture event (inner pixels). Prefer control unless you already hold pixels.
destroy()void—Tear down listeners and observers. Call it when you unmount the element — a resize-observing chart outlives its node otherwise.
Returns / emits

change is the seam to the rest of your app: a survey posts getData() on submit, a live app writes it through on every commit.

A minimal chart

Three pieces make a static chart: schema (what each field is and its domain), data (the rows), and marks (the marks that encode those rows). That is the whole model until you attach an edit.

A bar mark

schema + data + bar({ channels }). x is a band of categories, y a linear value, fill a constant.

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 34 },
  data: [
    { cat: "A", n: 30 }, { cat: "B", n: 55 },
    { cat: "C", n: 22 }, { cat: "D", n: 44 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 60] },
  },
  marks: [
    bar({
      fill: "#4f46e5",
      channels: {
        x: { field: "cat" },
        y: { field: "n" },
      },
    }),
  ],
}))

Encoding, and its inverse

Attach an edit to a channel and a gesture writes that channel back through the same scale. The bar below is identical to the one above, except y now carries edit: move() — so encoding (data → height) gains its inverse (drag → data).

The same bar, now editable

y carries edit: move(). Dragging a bar writes its value back to the data.

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 34 },
  data: [
    { cat: "A", n: 30 }, { cat: "B", n: 55 },
    { cat: "C", n: 22 }, { cat: "D", n: 44 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 60] },
  },
  marks: [
    bar({
      fill: "#4f46e5",
      channels: {
        x: { field: "cat" },
        y: { field: "n", edit: move() },
      },
    }),
  ],
}))
Try: Drag a bar up or down.

Reading the answer

Committed data leaves the chart through onChange, getData(), or chart.on("change", …). Hover previews never fire these — only a finished edit does.

onChange / getData

onChange logs each commit. getData() returns a deep copy of the elicited rows; on("change") is the same seam as a listener.

const chart = mount(Elicit({
  width: 380, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 34 },
  data: [
    { cat: "A", n: 30 }, { cat: "B", n: 55 },
    { cat: "C", n: 22 }, { cat: "D", n: 44 },
  ],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n:   { type: "quantitative", domain: [0, 60] },
  },
  onChange: (d) => console.log("elicited", d),
  marks: [
    bar({
      fill: "#4f46e5",
      channels: {
        x: { field: "cat" },
        y: { field: "n", edit: move() },
      },
    }),
  ],
}))
// chart.getData()  — deep copy of the committed rows
// chart.on("change", (d) => …)  — same commits, as a listener
Try: Drag a bar — open the console to see the committed rows.
