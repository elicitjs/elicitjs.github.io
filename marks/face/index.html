Face (emotion)

face encodes emotion — a datum's fields — into a face, and lets you directly manipulate the features to write them back: pull the mouth into a smile, widen an eye, tilt a brow. It is a preset, not a mark: it returns a composite in box mode — a point head, two ellipse eyes, two tickY brows and a curveY mouth — each placed in the glyph's own local units. Each parameter is a channel on one of those parts, so it takes the ordinary edits and is only editable when you bind it to a field.

API reference

face(options)

Import from elicit.plot. A preset, not a mark: it returns a composite in box mode — a head point, two ellipse eyes, two tickY brows and a curveY mouth — each placed in the glyph’s own local units. So every feature is its own drag target, and every parameter takes the universal edits. Its centre is placed by the x/y channels when present, else parked at the plot centre.

Returns / emits

An array of features (Elicit flattens it): the composite’s box — which draws one invisible hit circle per row, so move() / resize() on x/y/size picks the whole face up — then head, eyes, brows and mouth.

One face — drag to feel

The emotion preset binds mouthCurve to valence and eyeScale to arousal. Grab the mouth and pull it up to smile, or drag an eye to widen it — each gesture inverts through the field's scale, and the whole face re-derives.

Because every feature is its own mark, the edits are the ones you already know: a slide on the mouth's curvature, a slide on an eye's radius. There is no edit.face.* namespace.

Valence × arousal

The two-field emotion preset. The mouth and eyes are the drag targets themselves.

mount(Elicit({
  width: 320, height: 320,
  margins: { top: 12, right: 12, bottom: 12, left: 12 },
  data: [ { valence: 0.3, arousal: 0.1 } ],
  schema: {
    valence: { type: "quantitative", domain: [-1, 1] },
    arousal: { type: "quantitative", domain: [-1, 1] },
  },
  marks: [
    // A face draws its features but writes nothing until an edit says so. The
    // emotion preset binds mouthCurve ← valence and eyeScale ← arousal; declaring
    // them here is what makes those two columns editable — and says which they are.
    // Each param is a channel on a real part, so it takes the ordinary edits.
    face({
      channels: {
        mouthCurve: { field: "valence", edit: slide({ axis: "y", increase: "up" }) },
        eyeScale:   { field: "arousal", edit: slide({ axis: "x", increase: "right" }) },
      },
    }),
  ],
}))
Try: Drag the mouth up/down (valence) or drag an eye sideways (arousal).

Turn on more expressions

Bind any subset of the six params in channels, each a plain { field } with the edit you want. Unbound params stay neutral. Here every param is live: the mouth (↕ curve, ↔ smirk), the eyes (↔ aperture, ↕ squint), and the brows (↕ height, ↔ tilt).

Two params on one part means one gesture drives both — dragging an eye sideways opens it and dragging it down squints it, because rx and ry are two channels on one ellipse. The rule for sharing a part is that the two edits must read different components of the drag: one on axis: "x", one on axis: "y". That is also why a brow's tilt slides rather than rotating, even though it drives an angle. You grab a brow at its own pivot, so an angular edit would swing through most of a half-turn in a few pixels and pin the value to an extreme — the sensitivity of rotate comes from the pointer's distance to the pivot, and inside a glyph that distance is nearly zero.

Full Chernoff face

All six parameters bound to fields; grab any feature to sculpt the expression.

mount(Elicit({
  width: 340, height: 340,
  margins: { top: 12, right: 12, bottom: 12, left: 12 },
  data: [ {
    curve: 0.7, smirk: 0.5,
    aperture: 0.6, squint: 0.2, browH: 0.5, browT: 0.4,
  } ],
  schema: {
    curve:    { type: "quantitative", domain: [0, 1] },
    smirk:    { type: "quantitative", domain: [0, 1] },
    aperture: { type: "quantitative", domain: [0, 1] },
    squint:   { type: "quantitative", domain: [0, 1] },
    browH:    { type: "quantitative", domain: [0, 1] },
    browT:    { type: "quantitative", domain: [0, 1] },
  },
  marks: [
    face({
      channels: {
        // The mouth is one part, so one drag drives both of its params: the
        // vertical component bends it, the horizontal one tilts it into a smirk.
        mouthCurve: { field: "curve", edit: slide({ axis: "y", increase: "up" }) },
        mouthAsym:  { field: "smirk", edit: slide({ axis: "x", increase: "right" }) },
        // Each eye is one ellipse: rx opens it, ry squints it. Horizontal and
        // vertical drag, so one gesture on an eye reads as reshaping it.
        eyeScale:  { field: "aperture", edit: slide({ axis: "x", increase: "right" }) },
        eyeSquint: { field: "squint",   edit: slide({ axis: "y", increase: "down" }) },
        // Each brow is one tick: height is where it SITS — a positional channel in
        // the face's frame, so `move()` inverts straight back through it — and tilt
        // is a magnitude, so it slides.
        browHeight: { field: "browH", edit: move({ channels: ["y"] }) },
        browTilt:   { field: "browT", edit: slide({ axis: "x", increase: "right" }) },
      },
    }),
  ],
}))
Try: Drag the mouth, an eye, or a brow — each is a separate mark.

Many faces in a plot

Give the face an x (or y) channel and it is placed like a point — one editable face per row, each with its own frame. Set x: { field: 'valence' }, y: { field: 'arousal' } instead and the faces become an emotion-space scatter that moves as you edit them.

A mood per person

Faces positioned along a categorical x; drag each one's mouth or eyes to set that person's emotion.

mount(Elicit({
  width: 540, height: 260,
  margins: { top: 16, right: 20, bottom: 34, left: 20 },
  axes: { x: {}, y: false },
  data: [
    { who: "Ana", valence: 0.6, arousal: 0.4 },
    { who: "Ben", valence: -0.5, arousal: -0.2 },
    { who: "Cy",  valence: 0.1, arousal: 0.8 },
  ],
  schema: {
    who:     { type: "categorical", domain: ["Ana", "Ben", "Cy"] },
    valence: { type: "quantitative", domain: [-1, 1] },
    arousal: { type: "quantitative", domain: [-1, 1] },
  },
  marks: [
    face({
      size: 46,
      channels: {
        x: { field: "who" },
        // Declared, not implied: these are the two columns a drag on this face
        // writes. (The emotion preset would DRAW the same binding, but a mark is
        // inert until an edit names the column it touches.) Every face's parts are
        // separate features, so a drag on Ana's mouth cannot reach Ben's.
        mouthCurve: { field: "valence", edit: slide({ axis: "y", increase: "up" }) },
        eyeScale:   { field: "arousal", edit: slide({ axis: "x", increase: "right" }) },
      },
    }),
  ],
}))
Try: Drag any face's mouth or an eye.

Move and resize the head

The head is an ordinary point, so it takes an ordinary move(): bind x and y to fields, attach the edit, and grabbing the head drags the glyph through the plane. The eyes, brows and mouth are separate features drawn on top of it, so grabbing one of them still edits the expression — direct-pick dispatch routes a gesture to the touched node's feature, and nothing has to arbitrate.

size is both the head's radius and the frame's half-size, so a resize() on it scales every feature with it. Keep it off a face that is also movable, though: both would be direct edits on the same head, and one drag would fire both.

Drag the head to move it

x + y bound with move() on the head part. The mouth and eyes still edit the emotion preset.

mount(Elicit({
  width: 340, height: 320,
  margins: { top: 12, right: 12, bottom: 12, left: 12 },
  data: [ { px: 0.1, py: 0.1, valence: 0.4, arousal: 0.2 } ],
  schema: {
    px:      { type: "quantitative", domain: [-1, 1] },
    py:      { type: "quantitative", domain: [-1, 1] },
    valence: { type: "quantitative", domain: [-1, 1] },
    arousal: { type: "quantitative", domain: [-1, 1] },
  },
  marks: [
    face({
      size: 62,
      channels: {
        // The head is an ordinary `point`, so it takes an ordinary `move()`. The
        // eyes, brows and mouth are separate features drawn on top of it, so
        // grabbing one of them edits the expression instead — no arbitration.
        x: { field: "px", edit: move({ channels: ["x", "y"] }) },
        y: { field: "py" },
        mouthCurve: { field: "valence", edit: slide({ axis: "y", increase: "up" }) },
        eyeScale:   { field: "arousal", edit: slide({ axis: "x", increase: "right" }) },
      },
    }),
  ],
}))

Resize the whole glyph

size bound with resize(): the head grows and the eyes, brows and mouth grow with it, because they are placed in fractions of the frame.

mount(Elicit({
  width: 340, height: 320,
  margins: { top: 12, right: 12, bottom: 12, left: 12 },
  data: [ { mag: 55, valence: 0.4 } ],
  schema: {
    mag:     { type: "quantitative", domain: [30, 90] },
    valence: { type: "quantitative", domain: [-1, 1] },
  },
  marks: [
    face({
      channels: {
        // `size` is the head's radius AND the frame's half-size, so resizing it
        // scales every feature with it. Give it a radius range — the default size
        // range is the small [3, 18] a dot uses.
        size: { field: "mag", scale: { range: [30, 92] }, edit: resize() },
        mouthCurve: { field: "valence", edit: slide({ axis: "y", increase: "up" }) },
      },
    }),
  ],
}))
Try: Drag the head outward to grow it, inward to shrink it.

Showing a handle's track

A positional channel in the frame is a real scale, so an edit that inverts the pointer through it — move() — travels exactly the range the scale spans, and no further. guide: \{ track: true \} draws that range: the dashed segment is the mapping itself, not a redrawing of it. Opt-in, because where the range is obvious it is only extra ink.

A handle's travel range

The dashed segment is exactly the range the edit maps the pointer onto — drag past either end and the value stops.

mount(Elicit({
  width: 320, height: 300,
  margins: { top: 12, right: 12, bottom: 12, left: 12 },
  data: [ { brow: 0.5 } ],
  schema: {
    brow: { type: "quantitative", domain: [0, 1] },
  },
  marks: [
    face({
      channels: {
        // A brow's height is a POSITIONAL channel in the face's local frame, so
        // `move()` inverts the pointer straight back through the very scale that
        // placed it — and the frame scale's pixel range IS the travel range.
        // `guide: { track: true }` draws that range, so what you see is the mapping.
        browHeight: {
          field: "brow",
          edit: move({ channels: ["y"], guide: { track: true } }),
        },
      },
    }),
  ],
}))
Try: Drag a brow up and down along its dashed track.

One face per day — click to add

A face is a data glyph, so it's creatable like a point: a plane click inverts the pointer through the x and y scales to mint a datum, and every part draws itself from it. Mark-level edits ride on the head part, so the create fires once per click rather than once per facial feature.

Here the week starts with three days filled; click an empty day to add its face — the click's height sets the mood, which also drives the smile. unique({ field: "day" }) makes the day the identity, so each day holds at most one face.

Click an empty day to add a face

create() on an ordinal x (days) × numeric y (mood); unique({ field: "day" }) caps each day at one face. mouthCurve reads the same mood field, so a created face's smile matches where you clicked.

mount(Elicit({
  width: 560, height: 300,
  margins: { top: 16, right: 20, bottom: 32, left: 34 },
  axes: { x: {}, y: {} },
  data: [
    { day: "Mon", mood: 0.7 },
    { day: "Wed", mood: 0.4 },
    { day: "Sat", mood: 0.9 },
  ],
  schema: {
    // Ordinal x: the week runs Mon → Sun in this order (a band axis).
    day:  { type: "ordinal", domain: ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"] },
    // Numeric y in [0, 1]: how good the day felt. It also drives the smile.
    mood: { type: "quantitative", domain: [0, 1] },
  },
  constraints: [ unique({ field: "day" }) ],
  marks: [
    face({
      size: 24,
      channels: {
        x: { field: "day" },
        y: { field: "mood" },
        // Bind the smile to the SAME field as y: click higher → happier face,
        // and a created face's expression derives from the mood create mints —
        // no extra field to seed. The edit makes pulling the mouth write `mood`
        // too, so the smile and the y position stay two views of one column.
        mouthCurve: { field: "mood", edit: slide({ axis: "y", increase: "up" }) },
      },
      // A click on an empty day's column inverts the pointer to (day, mood) and
      // mints one face there. Mark-level edits ride on the HEAD part, so the
      // create fires once per click, not once per facial feature. A click that
      // lands ON a face carries a node, so it never fires the plane create — and
      // a click in a day that's already taken is rejected by `unique`.
      edits: [ create({ channels: ["x", "y"] }) ],
    }),
  ],
}))

It's just a composite

face() builds nothing you couldn't assemble yourself. Below is a smaller version written out in full — a point head, two ellipse eyes, two tickY brows and a curveY mouth, each placed in the composite's box.

Read frame: as "this number is in the glyph's own coordinates": x and y in [-1, 1] from the centre with y up, radii as a fraction of the half-size. A part that states no position sits at the centre, which is where the head goes. A field-bound channel maps the field's declared domain onto a slice of the box (frame: [0.05, 0.19]), and the edit inverts back through it.

Each brow is a tickY spanning a chord, with worry driving its height and its tilt. The two tilt ranges are mirrored — [45, -45] on the left, [-45, 45] on the right — so a rising worry tilts both brows into the same expression rather than the same direction. A frame: scale belongs to its own part, so the two ranges don't collide.

A face, written out

The same construction face() performs, spelled out with composite + point + ellipse + tick + curve.

mount(Elicit({
  width: 320, height: 300,
  margins: { top: 12, right: 12, bottom: 12, left: 12 },
  data: [ { openness: 0.7, mood: 0.8, worry: 0.35 } ],
  schema: {
    openness: { type: "quantitative", domain: [0, 1] },
    mood:     { type: "quantitative", domain: [0, 1] },
    worry:    { type: "quantitative", domain: [0, 1] },
  },
  marks: [
    // This is what `face()` returns. A part stating a `frame:` channel turns the
    // composite into a BOX: its x / y / size say where the box is and how big,
    // and a `frame:` channel is placed inside it — x and y in [-1, 1] from the
    // centre with y UP, radii as a fraction of the half-size.
    composite({
      id: "myface",
      channels: { size: { value: 92 } },
      parts: [
        // The head IS the box: radius 1 in local units, and no position at all —
        // inside a box, saying nothing means "here, at the glyph".
        point({ channels: {
          size:   { frame: 1 },
          fill:   { value: "#FFD666" },
          stroke: { value: "#B7791F" },
        } }),
        // Two eyes. `rx` maps the field's domain onto a slice of the box, so the
        // same drag means the same thing however big the head is.
        ellipse({ channels: {
          x:  { frame: -0.4 },
          y:  { frame: 0.16 },
          rx: { field: "openness", frame: [0.05, 0.19],
                edit: slide({ axis: "x", increase: "right" }) },
          ry: { frame: 0.12 },
          fill: { value: "#1f2937" },
        } }),
        ellipse({ channels: {
          x:  { frame: 0.4 },
          y:  { frame: 0.16 },
          rx: { field: "openness", frame: [0.05, 0.19],
                edit: slide({ axis: "x", increase: "right" }) },
          ry: { frame: 0.12 },
          fill: { value: "#1f2937" },
        } }),
        // Two brows, each a tickY spanning a chord in the box. `worry` drives
        // BOTH the height (a slide on y) and the tilt — and the two tilt ranges
        // are MIRRORED, so one rising field tilts them into the same expression
        // rather than the same direction. That only works because each part's
        // frame scale is PRIVATE: a single global angle scale could not hold
        // [45, -45] and [-45, 45] at once.
        tickY({ channels: {
          x1: { frame: -0.14 }, x2: { frame: -0.50 },
          y:  { field: "worry", frame: [0.57, 0.23],
                edit: slide({ axis: "y", increase: "down" }) },
          angle: { field: "worry", frame: [45, -45] },
          stroke: { value: "#1f2937" },
          strokeWidth: { frame: 0.055 },
        } }),
        tickY({ channels: {
          x1: { frame: 0.14 }, x2: { frame: 0.50 },
          y:  { field: "worry", frame: [0.57, 0.23],
                edit: slide({ axis: "y", increase: "down" }) },
          angle: { field: "worry", frame: [-45, 45] },
          stroke: { value: "#1f2937" },
          strokeWidth: { frame: 0.055 },
        } }),
        // The mouth is a `curve`: a chord in the box plus a curvature. Positive
        // bows up, so a descending range turns a rising mood into a deeper smile.
        curveY({ channels: {
          x1: { frame: -0.36 },
          x2: { frame: 0.36 },
          y:  { frame: -0.34 },
          curvature: { field: "mood", frame: [0.6, -0.6],
                       edit: slide({ axis: "y", increase: "up" }) },
          stroke: { value: "#1f2937" },
          strokeWidth: { frame: 0.055 },
        } }),
      ],
    }),
  ],
}))
