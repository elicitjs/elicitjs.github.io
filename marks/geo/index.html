Geo

Geographic marks for map elicitation. Set a chart-level projection — "mercator", { type, domain, … }, or a live d3.geo* instance. Position goes through that projection's apply/invert, not x/y scales. Provide basemap topology with geoBasemap({ geojson }), a GeoJSON FeatureCollection, Feature, or Geometry. Editable overlays live on the dataset, like every other mark. Examples below use Vancouver's 22 local areas (vancouver in the docs scope) — swap in your own file.

API reference

projection (ElicitSpec)

Chart option. Built once per layout into scales.projection with apply, invert, and path. Fit with domain: geojson. Auto axes default off when set.

projection: "mercator" | "albers-usa" | "equirectangular" | …
projection: { type, domain?, rotate?, inset?, … }

geoBasemap({ geojson, … })

Inert background map. Pass topology as a mark option — geojson — not as Elicit data. Load your own: const map = await fetch("…").then(r => r.json()) then geoBasemap({ geojson: map }). A FeatureCollection draws one path per feature so boundaries show.

geoBasemap({ geojson, fill, stroke, strokeWidth, id }) → Feature
Options
OptionTypeDefaultDescription
geojsonGeoJSON—FeatureCollection, Feature, or Geometry. Required for a visible basemap.
fill / stroke / strokeWidthstyle'#e2e8f0' / '#94a3b8' / 0.75Chrome styling (also via channels).

geoTile({ url, … })

Raster basemap from a slippy-map tile server (OSM, CARTO, satellite, your own) — the Leaflet model. Requires projection: "mercator": tiles are images baked in Web Mercator and cannot register under another projection (the mark verifies this by behaviour, not by name, and warns instead of misaligning). Chrome, like geoBasemap — takes no data. Compose the two to draw boundaries over imagery.

A Feature emitting image nodes into the background layer, keyed by {z}/{x}/{y} so on-screen tiles survive a re-render without re-fetching.

geoPoint / geoPolygon / geoLine / geoText / geoRect

Editable overlays. Import from elicit.plot. geoText is text with the projection doing the placement — it shares the node shape, so editText / cycle / rotate work on it unchanged.

geoPolygon({ channels: { geometry, fill } }) → Feature
geoLine({ channels: { coordinates }, curve, showVertices }) → Feature  // one line per row
geoLine({ channels: { lon, lat, series, order }, connect }) → Feature  // one path across rows
geoText({ channels: { lon, lat, text }, dx, dy, format }) → Feature
geoRect({ channels: { west, south, east, north } }) → Feature

edit.geo.*

Geo-scoped edits (scope: "geo"). Invert the pointer through the chart projection.

edit.geo.move() — move a geoPoint
edit.geo.create() — click to place a lon/lat row
edit.geo.draw({ minDist }) — drag to author a coordinates list (minDist: 8 px per vertex)
edit.geo.dragVertex() — move a geoLine vertex handle
edit.geo.removeVertex({ min }) — click a vertex away (min: 2 vertices kept)
edit.geo.brush({ move, edgeInset }) — resize/move a geoRect
edit.geo.createRect({ width, height, edgeInset }) — click open map to mint a bbox (degrees)

Providing basemap data

The basemap is chrome. Pass GeoJSON into geoBasemap, and fit the projection with that same object as domain so the map fills the frame. Below, vancouver is the docs sample (22 local areas) — your app would import or fetch its own.

Vancouver local areas

Pass any FeatureCollection: geoBasemap({ geojson }). Fit with projection.domain. In your app: const map = await fetch("…/my-map.geojson").then(r => r.json()).

// docs inject `vancouver`; your app loads GeoJSON then passes it in:
// const vancouver = await fetch("data/vancouver-neighborhoods.json").then(r => r.json());

mount(Elicit({
  width: 520, height: 360,
  margins: { top: 8, right: 8, bottom: 8, left: 8 },
  projection: { type: "mercator", domain: vancouver, inset: 6 },
  data: [],
  schema: {},
  marks: [
    geoBasemap({
      geojson: vancouver,
      fill: "#e8eef5",
      stroke: "#64748b",
      strokeWidth: 0.8,
    }),
  ],
}));

Real basemaps (OSM raster tiles)

geoTile() lays a raster basemap — a pyramid of 256px tiles from a tile server — behind your marks. Tiles are pre-rendered in Web Mercator, so it requires projection: "mercator"; other projections draw nothing and log a warning instead of a misaligned map. Your lon/lat marks and edit.geo.* gestures work the same on top, since they still go through the same projection. Attribution is a licence condition of every tile service, and is drawn by default. Public OSM tiles are rate-limited — point url at your own server or a paid provider in production.

Pins on OpenStreetMap

geoTile() replaces geoBasemap entirely — no GeoJSON needed. The projection still needs a domain to know where to look; a bbox works when you have no topology to fit.

mount(Elicit({
  width: 520, height: 360,
  margins: { top: 8, right: 8, bottom: 8, left: 8 },
  // No GeoJSON: fit the projection to a lon/lat box. Mind the ring winding —
  // counterclockwise (RFC 7946). Reversed, d3 reads the box as the whole globe
  // and the map zooms out to the world.
  projection: {
    type: "mercator",
    domain: {
      type: "Polygon",
      coordinates: [[
        [-123.225, 49.198], [-123.225, 49.297],
        [-123.023, 49.297], [-123.023, 49.198], [-123.225, 49.198],
      ]],
    },
  },
  data: [
    { lon: -123.1207, lat: 49.2827, place: "Downtown" },
    { lon: -123.1560, lat: 49.2680, place: "Kitsilano" },
  ],
  schema: {
    lon:   { type: "quantitative", domain: [-123.27, -123.02] },
    lat:   { type: "quantitative", domain: [49.20, 49.32] },
    place: { type: "categorical" },
  },
  marks: [
    geoTile(),   // defaults to OSM standard + its attribution

    geoPoint({
      size: 7, fill: "#dc2626", stroke: "#fff", strokeWidth: 2,
      channels: {
        lon: { field: "lon" },
        lat: { field: "lat" },
      },
      edits: [edit.geo.move(), edit.geo.create({ defaults: { place: "new pin" } })],
    }),
  ],
}));
Try: Click to drop a pin; drag it. Lon/lat come back as data.

Tiles under the neighborhood outlines

Raster and vector chrome compose: geoTile() lays the imagery, geoBasemap() draws the boundaries over it (fill "none"), and the elicited marks sit on top of both. Dim the tiles with opacity so your data still reads.

mount(Elicit({
  width: 520, height: 360,
  margins: { top: 8, right: 8, bottom: 8, left: 8 },
  projection: { type: "mercator", domain: vancouver, inset: 6 },
  data: [{ name: "study area", west: -123.140, south: 49.275, east: -123.100, north: 49.290 }],
  schema: {
    name:  { type: "categorical" },
    west:  { type: "quantitative", domain: [-123.27, -123.02] },
    south: { type: "quantitative", domain: [49.20, 49.32] },
    east:  { type: "quantitative", domain: [-123.27, -123.02] },
    north: { type: "quantitative", domain: [49.20, 49.32] },
  },
  marks: [
    // A lighter, less busy basemap than OSM standard. Any {z}/{x}/{y} server works.
    geoTile({
      url: "https://{s}.basemaps.cartocdn.com/light_all/{z}/{x}/{y}.png",
      subdomains: ["a", "b", "c"],
      opacity: 0.85,
      attribution: "© OpenStreetMap · © CARTO",
    }),

    // Vector boundaries on top of the imagery.
    geoBasemap({ geojson: vancouver, fill: "none", stroke: "#1e293b", strokeWidth: 0.8 }),

    geoRect({
      fill: "rgba(37, 99, 235, 0.18)", stroke: "#1d4ed8", strokeWidth: 1.5,
      channels: {
        west:  { field: "west" },
        south: { field: "south" },
        east:  { field: "east" },
        north: { field: "north" },
      },
      edits: [
        edit.geo.brush({ edgeInset: 10 }),
        edit.geo.createRect({ width: 0.024, height: 0.014, defaults: { name: "new area" } }),
      ],
    }),
  ],
}));
Try: Drag a study box; click open map to add one.

Label and rename places

geoText is a text mark positioned by the projection instead of x/y scales — that's the only geo-specific part, so every other text behaviour carries over: editText() to retype the content, cycle() to advance a categorical label, rotate() on angle. Pair it with a geoPoint as a separate mark reading the same rows, and dragging the dot moves the label along with it. dx/dy offset the glyph from its anchor without touching the lon/lat a drag writes.

Named pins you can rename

geoPoint carries the drag; geoText carries the label. editText() opens an inline editor on double-click and writes the string back to the row.

mount(Elicit({
  width: 520, height: 360,
  margins: { top: 8, right: 8, bottom: 8, left: 8 },
  projection: { type: "mercator", domain: vancouver, inset: 6 },
  data: [
    { lon: -123.1207, lat: 49.2827, place: "Downtown" },
    { lon: -123.1560, lat: 49.2680, place: "Kitsilano" },
    { lon: -123.1000, lat: 49.2630, place: "Mt Pleasant" },
  ],
  schema: {
    lon:   { type: "quantitative", domain: [-123.27, -123.02] },
    lat:   { type: "quantitative", domain: [49.20, 49.32] },
    place: { type: "categorical" },
  },
  marks: [
    geoBasemap({ geojson: vancouver, fill: "#eef2f7", stroke: "#94a3b8", strokeWidth: 0.7 }),

    geoPoint({
      size: 6, fill: "#0f766e", stroke: "#fff", strokeWidth: 1.5,
      channels: {
        lon: { field: "lon" },
        lat: { field: "lat" },
      },
      edits: [edit.geo.move(), edit.geo.create({ defaults: { place: "new place" } })],
    }),

    // The label: same rows, positioned by the same projection, nudged above the dot.
    geoText({
      dy: -12, fontSize: 12, fill: "#0f172a",
      channels: {
        lon:  { field: "lon" },
        lat:  { field: "lat" },
        text: { field: "place" },
      },
      edits: [editText({ channel: "text" })],
    }),
  ],
}));
Try: Double-click a name to retype it · drag a dot (the label follows) · click the map to add a pin.

Recolour neighborhoods

Editable regions are dataset rows with a geometry field, a subset of the basemap features promoted into data. The basemap stays inert chrome underneath.

Cycle fill on selected local areas

Kitsilano, Fairview, Mount Pleasant, Downtown — click to cycle category.

const editable = vancouver.features
  .filter(f => ["Kitsilano", "Fairview", "Mount Pleasant", "Downtown"].includes(f.properties.name))
  .map(f => ({
    name: f.properties.name,
    geometry: f.geometry,
    fill: "A",
  }));

mount(Elicit({
  width: 520, height: 360,
  margins: { top: 8, right: 8, bottom: 8, left: 8 },
  projection: { type: "mercator", domain: vancouver, inset: 6 },
  data: editable,
  schema: {
    name: { type: "categorical" },
    fill: { type: "categorical", domain: ["A", "B", "C"] },
    geometry: { type: "categorical" },
  },
  marks: [
    geoBasemap({ geojson: vancouver, fill: "#f1f5f9", stroke: "#94a3b8", strokeWidth: 0.7 }),
    geoPolygon({
      stroke: "#0f172a", strokeWidth: 1.2, fillOpacity: 0.75,
      channels: {
        geometry: { field: "geometry", scale: null },
        fill: {
          field: "fill",
          scale: { scheme: "tableau10" },
          edit: cycle(),
        },
      },
    }),
  ],
}));
Try: Click a shaded neighborhood to cycle its colour.

Connected scatter over the map

Give geoLine lon/lat channels instead of coordinates and it connects the dataset's rows into one path, the geographic sibling of path. Points are a separate geoPoint mark reading the same rows, so dragging a stop re-derives the trail on the next render. Order defaults to "sequence" (array order); pass a field name to sort by it, or series to draw one trail per group.

A route across Vancouver

Five stops connected in `stop` order. The dots are a geoPoint mark with edit.geo.move() — the trail follows because both marks read the same dataset.

mount(Elicit({
  width: 520, height: 360,
  margins: { top: 8, right: 8, bottom: 8, left: 8 },
  projection: { type: "mercator", domain: vancouver, inset: 6 },
  data: [
    { stop: 1, lon: -123.1850, lat: 49.2720, place: "Kitsilano" },
    { stop: 2, lon: -123.1480, lat: 49.2660, place: "Fairview" },
    { stop: 3, lon: -123.1150, lat: 49.2640, place: "Mount Pleasant" },
    { stop: 4, lon: -123.1000, lat: 49.2790, place: "Strathcona" },
    { stop: 5, lon: -123.1207, lat: 49.2870, place: "Downtown" },
  ],
  schema: {
    stop:  { type: "quantitative" },
    lon:   { type: "quantitative", domain: [-123.27, -123.02] },
    lat:   { type: "quantitative", domain: [49.20, 49.32] },
    place: { type: "categorical" },
  },
  marks: [
    geoBasemap({ geojson: vancouver, fill: "#eef2f7", stroke: "#94a3b8", strokeWidth: 0.7 }),

    // The connector: lon/lat channels -> one path across the rows, in `stop` order.
    geoLine({
      stroke: "#b91c1c", strokeWidth: 2, curve: "linear",
      channels: {
        lon: { field: "lon" },
        lat: { field: "lat" },
        // `order` is a channel: it names the column the trail is sorted by.
        order: { field: "stop" },
      },
    }),

    // The stops: their own feature, so a drag lands on one dot.
    geoPoint({
      size: 6, fill: "#b91c1c", stroke: "#fff", strokeWidth: 1.5,
      channels: {
        lon: { field: "lon" },
        lat: { field: "lat" },
      },
      edits: [edit.geo.move(), edit.geo.create({ defaults: { place: "new stop" } })],
    }),
  ],
}));
Try: Drag a stop to reroute; click the map to append one.

Geographic rectangles

Boxes are axis-aligned in lon/lat — they can look slightly curved under Mercator. Grab an edge or corner to reshape, the body to move, or click empty space to mint another. The zone you grab is fixed for the whole gesture, so a move never turns into a resize halfway through. The cursor shows which zone you're in before you press.

Study areas over the city

edit.geo.brush() resizes + moves; edit.geo.createRect() mints a new box on a click in open space (clicking an existing box grabs it instead). Pass move:false for resize-only, or { edgeInset } to widen the grab band.
