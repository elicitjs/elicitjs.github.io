Ellipse

ellipse is a dot with two independent radii. A point has one size channel because a circle has one radius; splitting it into rx and ry means each is its own magnitude channel — each can carry its own field, and each can carry its own edit. A shape that widens on one drag and flattens on another is two elicited numbers in one mark.

API reference

ellipse(options)

Import from elicit.plot. A dot with two independent radii. point has one size channel because a circle has one radius; splitting it into rx and ry means each can carry its own field and its own edit — two elicited numbers in one shape.

ellipse({ channels, edits, id }) → Mark
Options
OptionTypeDefaultDescription
channelsChannels{}x, y, rx, ry, angle plus the standard style channels.
sizenumber | ChannelSpec5The fallback for whichever radius is not otherwise named, so ellipse({ size: 6 }) is a circle.
fill, stroke, …styletheme inkThe standard style surface, same as every mark.
Channels
ChannelTypeDescription
x, ylinear | band | pointThe centre. A missing channel parks it at the centre of that dimension.
rxsizeHorizontal radius in px (default range [3, 18]). Natural edit: slide({ axis: 'x' }).
rysizeVertical radius in px. Natural edit: slide({ axis: 'y' }). Both fall back to size.
anglelinearTilt in math degrees about the centre. A rotated ellipse is hit-tested in its own frame, so it stays grabbable where it is drawn.
Returns / emits

A mark emitting one ellipse node per datum.

Two uncertainties, one blob

The classic use is an estimate with per-axis uncertainty: the centre is what someone believes, and the two radii are how sure they are along each axis separately. A circle can only say "unsure overall"; this can say "confident about cost, vague about benefit".

Both radius edits live on the same mark, so a single diagonal drag reshapes the blob. That's fine here — slide({ axis: 'x' }) and slide({ axis: 'y' }) read different components of the gesture, so neither fights the other.

Cost × benefit, with per-axis spread

rx and ry are separate fields; drag a blob sideways to widen it, up or down to flatten it.

mount(Elicit({
  width: 480, height: 320,
  margins: { top: 20, right: 24, bottom: 40, left: 44 },
  axes: { x: {}, y: {} },
  data: [
    { region: "North", cost: 30, benefit: 62, costSd: 8,  benefitSd: 16 },
    { region: "South", cost: 66, benefit: 34, costSd: 17, benefitSd: 6 },
  ],
  schema: {
    cost:      { type: "quantitative", domain: [0, 100] },
    benefit:   { type: "quantitative", domain: [0, 100] },
    costSd:    { type: "quantitative", domain: [2, 30] },
    benefitSd: { type: "quantitative", domain: [2, 30] },
    region:    { type: "categorical", domain: ["North", "South"] },
  },
  marks: [
    // One blob per region: the CENTRE is the estimate, the two RADII are two
    // separate uncertainties. A circle could only say "how unsure overall"; two
    // radii let a reader say they are confident about cost and vague about benefit.
    // Both edits sit on one mark, so a single diagonal drag reshapes the blob —
    // that is the point of rx and ry being independent channels.
    ellipse({
      channels: {
        x: { field: "cost" },
        y: { field: "benefit" },
        rx: { field: "costSd",    scale: { range: [6, 64] },
              edit: slide({ axis: "x", increase: "right" }) },
        ry: { field: "benefitSd", scale: { range: [6, 64] },
              edit: slide({ axis: "y", increase: "down" }) },
        fill: { field: "region" },
        fillOpacity: { value: 0.35 },
        stroke: { field: "region" },
      },
    }),
  ],
}))
Try: Drag a blob sideways (cost spread) or vertically (benefit spread).

Moving it as well

Two edits that read the same component of a drag can't share one mark — one gesture would fire both, and a move() on the centre would fight a radius slide. Give them a mark each with a composite: an ellipse that resizes, and a point at its centre that moves. Direct-pick routes a gesture to the mark you touched, so nothing has to arbitrate.

A blob you can move and resize

The ellipse carries the radius edit; a small centre dot carries the move. Two marks, two gestures, one row.

mount(Elicit({
  width: 420, height: 320,
  margins: { top: 20, right: 24, bottom: 40, left: 44 },
  axes: { x: {}, y: {} },
  data: [ { cost: 40, benefit: 55, sd: 14 } ],
  schema: {
    cost:    { type: "quantitative", domain: [0, 100] },
    benefit: { type: "quantitative", domain: [0, 100] },
    sd:      { type: "quantitative", domain: [2, 30] },
  },
  marks: [
    // Two edits that both read a raw drag can't share one mark — one gesture would
    // fire both. Give them one mark each: the blob resizes, the dot at its centre
    // moves. Direct-pick routes a gesture to the mark you touched, so there is
    // nothing to arbitrate.
    composite({
      id: "blob",
      parts: [
        ellipse({ channels: {
          x: { field: "cost" },
          y: { field: "benefit" },
          rx: { field: "sd", scale: { range: [6, 64] },
                edit: slide({ axis: "x", increase: "right" }) },
          ry: { field: "sd", scale: { range: [6, 64] } },
          fill: { value: "#4e79a7" }, fillOpacity: { value: 0.28 },
          stroke: { value: "#4e79a7" },
        } }),
        point({ channels: {
          x: { field: "cost", edit: move({ channels: ["x", "y"] }) },
          y: { field: "benefit" },
          size: { value: 5 },
          fill: { value: "#1f2937" },
        } }),
      ],
    }),
  ],
}))
Try: Drag the dot to move the blob · drag the blob to resize it.

Inside a glyph

ellipse is what a face's eyes are: an rx that opens and an ry that squints, both stated as fractions of the glyph's frame so they scale with the head. See composite for how a mark places itself in a glyph's local coordinates.
