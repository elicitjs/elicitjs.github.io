Legend

A key for one encoding — a field on a non-positional channel like fill, size or symbol. Declare it where the encoding is (fill: \{ field, legend: true \}) and the legend knows exactly which scale it draws. Unlike an axis it reserves space on its side, so the plot shrinks and the legend never overlaps the marks. It can also be a picker: click a swatch to set a category, or drag a ramp handle to set a value, written straight back to the data.

API reference

ChannelSpec.legend · legendColor · legendSize · legendSymbol

A key for one encoding — a (channel, field) pair. Ask for it on the channel (fill: { field, legend: true }), chart-wide with legends: true, or by composing an element. The shape follows the channel: swatches, a colour ramp, graduated circles for size, a fan for angle, a weight stack for strokeWidth. It reserves space on its side, shrinking the plot so it never overlaps the marks. Elements import from elicit.elements.

legends: true   ·   legends: { fill: { anchor: 'top' }, size: false }

edit.legend.category · edit.legend.value

The legend pickers, written back through the normal edit pipeline. edit.legend.category() is a category picker (a direct-pick click on a swatch, whose value it sets). edit.legend.value() is a continuous value picker (a direct-pick drag on the ramp handle). Pass one to a legend’s edit option — the legend injects its channel.

edit.legend.value() → Edit      (drag the handle; maps to [lo,hi])

The legends key

A legend is a key for one encoding — a (channel, field) pair. That is the unit throughout: a scale belongs to an encoding, and a legend belongs to a scale.

There are three ways to ask for one, most specific first:

  1. an element you compose — legendColor(\{ field: "group" \})
  2. the channel — fill: \{ field: "group", legend: \{ anchor: "bottom" \} \}
  3. the chart — legends: true

Each wins over the ones below it. legends: \{ fill: false \} suppresses a channel; legend: false on a channel suppresses that one encoding.

legends defaults to off, unlike axes, because a legend reserves layout space; injecting one the moment a fill field appears would silently shrink the plot.

Two marks stating the same encoding share one scale and get one legend. Two marks with different fields on one channel are two encodings, so they get two scales and two keys — in different colour families, so they read as different things.

legends: true

One key per encoding, with no legend composed by hand.

mount(Elicit({
  width: 420, height: 240,
  margins: { top: 16, right: 16, bottom: 30, left: 34 },
  data: [
    { cat: "A", n: 40, team: "north" },
    { cat: "B", n: 65, team: "south" },
    { cat: "C", n: 28, team: "north" },
  ],
  schema: {
    cat:  { type: "categorical", domain: ["A", "B", "C"] },
    n:    { type: "quantitative", domain: [0, 100] },
    team: { type: "categorical", domain: ["north", "south"] },
  },
  // One legend per ENCODING — per (channel, field) pair, not per channel.
  // For per-channel config: `legends: { fill: { anchor: "top" }, size: false }`.
  legends: true,
  marks: [
    bar({
      channels: {
        x:    { field: "cat" },
        y:    { field: "n", edit: move() },
        fill: { field: "team" },
      },
    }),
  ],
}))

A discrete colour legend

legendColor() draws a swatch per category. It names no field: fill carries one encoding here, so there is one scale it could be a key for and the legend binds to it. anchor sets which side it's on, and the plot shrinks to leave room so the legend never overlaps the marks.

The title defaults to the encoded field's name, so a correct legend restates nothing the spec already said.

Swatches, reserving space

A categorical fill; the legend claims the right band and the bars shrink to fit.

mount(Elicit({
  width: 380, height: 220,
  margins: { top: 20, right: 16, bottom: 30, left: 40 },
  data: [
    { group: "North", value: 12 },
    { group: "South", value: 8 },
    { group: "East",  value: 15 },
    { group: "West",  value: 6 },
  ],
  schema: {
    group: { type: "categorical", domain: ["North", "South", "East", "West"] },
    value: { type: "quantitative", domain: [0, 16] },
  },
  marks: [
    barY({
      channels: {
        x: { field: "group" },
        y: { field: "value" },
        fill: { field: "group" },
      },
    }),
    // A legend for the fill channel, reserving space on the right so the bars
    // shrink to make room instead of drawing under it.
    legendColor({ anchor: "right" }),
  ],
}))

A continuous colour ramp

A quantitative fill resolves to a sequential colour scale, so the same legendColor() draws a gradient ramp with ticks instead of swatches — no extra option.

Gradient ramp

fill: { field: 'temp' } over a quantitative field becomes a ramp.

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 20, right: 16, bottom: 32, left: 44 },
  data: [
    { hour: 0, temp: 4 },  { hour: 3, temp: 6 },  { hour: 6, temp: 9 },
    { hour: 9, temp: 16 }, { hour: 12, temp: 24 }, { hour: 15, temp: 27 },
    { hour: 18, temp: 19 }, { hour: 21, temp: 11 },
  ],
  schema: {
    hour: { type: "quantitative", domain: [0, 24] },
    temp: { type: "quantitative", domain: [0, 30] },
  },
  marks: [
    point({
      size: 8,
      channels: {
        x: { field: "hour" },
        y: { field: "temp" },
        // A quantitative fill resolves to a SEQUENTIAL colour scale, so the
        // legend draws a gradient ramp with ticks instead of swatches.
        fill: { field: "temp" },
      },
    }),
    legendColor({ anchor: "right" }),
  ],
}))

A size legend

legendSize() over a quantitative field draws graduated circles at tick values, not a gradient — a size scale has no colour to ramp, so the key shows the sizes themselves.

The radii come from the scale, so the legend reports whichever one the channel resolved. size defaults to a linear radius, which keeps a drag predictable: the same pointer movement is the same change in value anywhere on the scale. Pass scale: "sqrt" on the channel for linear area instead, the perceptual convention for a static read, and the legend follows.

size: { field: "people", scale: "sqrt" }

A categorical size field gets swatches instead — one dot per category, at that category's radius.

Graduated circles

Nested circles at tick values, sized by the same scale as the dots.

Theta and stroke width

Every legendable channel gets a key shaped like the channel. theta draws a fan of spokes at their encoded bearings; strokeWidth draws a stack of segments at their encoded thicknesses. Both read the scale, so the key matches the marks.

Legendable channels are fill, stroke, size, symbol, opacity, theta and strokeWidth. (angle is a mark's rotation in place, not an encoding a reader looks up, so it has no key.) Asking for a legend on anything else logs a warning rather than drawing a shape that would misreport the scale — and for x/y, an axis is the key.

A fan and a weight stack

One needle mark encoding two channels; a key for each.

const rows = [
  { site: "A", x: 60,  bearing: 20,  flow: 2 },

  { site: "C", x: 220, bearing: 130, flow: 9 },
];
mount(Elicit({

  margins: { top: 18, right: 18, bottom: 22, left: 22 },

  schema: {
    site:    { type: "categorical",  domain: ["A", "B", "C"] },
    x:       { type: "quantitative", domain: [0, 280] },

    flow:    { type: "quantitative", domain: [0, 10] },

    // A needle per site: its ANGLE reads bearing, its WIDTH reads flow.

Any side

anchor: 'bottom' (or 'top') lays the swatches out in a row and reserves space on that side — past the axis, so it clears the x-axis labels.

A horizontal row below the x-axis; the plot height shrinks to fit.

A category picker

Pass edit: edit.legend.category() to make each swatch a click target that sets the channel's field on the target row (the first, by default).

Click a swatch to pick

A one-row belief whose category is set by clicking the legend.

mount(Elicit({
  width: 320, height: 170,
  margins: { top: 20, right: 16, bottom: 20, left: 20 },
  data: [ { group: "A" } ],
  schema: { group: { type: "categorical", domain: ["A", "B", "C", "D"] } },
  axes: false,
  marks: [
    // A one-row belief. The dot's colour reflects the current category.
    point({ size: 26, channels: { x: { value: 90 }, y: { value: 65 }, fill: { field: "group" } } }),
    // edit.legend.category() makes each swatch a click target that sets `group`.
    legendColor({ anchor: "right", edit: edit.legend.category() }),
  ],
}))

Two encodings on one channel

A scale belongs to one encoding, so two marks colouring by different fields get two scales — each with its own domain, its own colour family, and its own key. Neither has to be told which column it is about: the channel already said.

When you compose a legend by hand for a channel that carries two encodings, say which with field:

legendColor({ field: "goal" })

With one encoding on the channel it can be left out. With two and no field, the legend takes the first and logs a warning naming both — an ambiguity you can see rather than one silently resolved by declaration order.

table is the companion for a multi-table schema, naming which table the column is in. It is only needed when a hand-composed legend cannot get it from the encoding.

Two encodings on fill

Two scales, two keys, two colour families — and each picker writes its own column.

mount(Elicit({
  width: 340, height: 190,
  margins: { top: 20, right: 16, bottom: 20, left: 20 },
  data: [ { now: "low", goal: "mid" } ],
  schema: {
    now:  { type: "categorical", domain: ["low", "mid", "high"] },
    goal: { type: "categorical", domain: ["low", "mid", "high"] },
  },
  axes: false,
  marks: [
    // Two marks put DIFFERENT columns on `fill`. That is two encodings, so it
    // is two scales — different colour families, not one shared vocabulary.
    point({ size: 22, channels: { x: { value: 60 }, y: { value: 70 }, fill: { field: "now" } } }),
    point({ size: 22, channels: { x: { value: 60 }, y: { value: 115 }, fill: { field: "goal" } } }),
    text({ text: "now",  channels: { x: { value: 95 }, y: { value: 74 } }, textAnchor: "start", fontSize: 12 }),
    text({ text: "goal", channels: { x: { value: 95 }, y: { value: 119 } }, textAnchor: "start", fontSize: 12 }),
    // `field` NAMES the encoding each legend is a key for — the one case where
    // it is required, because the channel alone no longer identifies a scale.
    // It doubles as the title, so neither legend restates anything.
    legendColor({ anchor: "right", field: "now",  edit: edit.legend.category() }),
    legendColor({ anchor: "right", field: "goal", edit: edit.legend.category() }),
  ],
}))
Try: Click a swatch in either legend — each writes only its own column.

Declaring it on the channel

Putting legend: on the channel is the shortest way to a correct legend, because the channel already names the field and the mark already names the table. Nothing has to be restated, so nothing can disagree.

fill: { field: "group", legend: true }
fill: { field: "group", legend: { anchor: "bottom", title: "region" } }
fill: { field: "group", legend: false }   // suppress under legends: true

A picker goes in the same place. The gesture still happens on the legend — the mark's own bars are not click targets for it, and the edit is taken off the channel so they stay inert.

fill: { field: "group", legend: { edit: edit.legend.category() } }

Compose a legendColor() for the same encoding and it takes the edit instead of a separate key, so the mark says what is edited and the element says how it looks:

barY({ channels: { fill: { field: "group", legend: { edit: edit.legend.category() } } } }),
legendColor({ anchor: "bottom" }),

The picker on the fill channel

No legendColor() in the spec — the legend is built from the encoding.

  margins: { top: 20, right: 16, bottom: 30, left: 40 },

    { name: "A", value: 12, group: "North" },

    { name: "C", value: 15, group: "East"  },
    { name: "D", value: 6,  group: "West"  },
  ],
  schema: {
    name: { type: "categorical", domain: ["A", "B", "C", "D"] },
    group: { type: "categorical", domain: ["North", "South", "East", "West"] },
    value: { type: "quantitative", domain: [0, 16] },
  },
  marks: [
    barY({
      channels: {
        x: { field: "name" },
        y: { field: "value" },
        // The edit sits on the channel whose column it writes. There is no
        // legendColor() in this spec — the legend is minted for `fill`.

  ],
}))

Editing a selected item

Selection is pipeline state, not a data column: give the bars an edit.select() and a click selects one (the selected bar gets the highlight outline). The legend's row defaults to the selection, so the swatch you click edits the bar you picked — no selected field, no findIndex to keep in sync. See Selection for the full model.

The swatch the target row currently holds is ringed, so the legend shows what a click would replace as well as what it can set. A swatch names a value, not a row, so with nothing selected a picker has no target and no ring — the absence is the signal. The exception is a one-row table, which needs no selection to be unambiguous.

The swatches themselves never dim: a legend is a key first, and their fills are the encoding.

Pin row to a number, an array of indices, or a (data, { selection }) => index function to override.

Pick a bar, then edit its group

The bars carry edit.select(); the legend edits the selected bar. Nothing about selection touches the data.

mount(Elicit({
  width: 380, height: 220,
  margins: { top: 20, right: 16, bottom: 30, left: 40 },
  data: [
    { name: "A", value: 12, group: "North" },
    { name: "B", value: 8,  group: "South" },
    { name: "C", value: 15, group: "East"  },
    { name: "D", value: 6,  group: "West"  },
  ],
  schema: {
    name: { type: "categorical", domain: ["A", "B", "C", "D"] },
    group: { type: "categorical", domain: ["North", "South", "East", "West"] },
    value: { type: "quantitative", domain: [0, 16] },
  },
  marks: [
    // Click a bar to SELECT it. Selection is pipeline state (no `selected` column);
    // the selected bar gets the highlight outline automatically.
    barY({
      channels: {
        x: { field: "name" },
        y: { field: "value" },
        fill: { field: "group" },
      },

    // The legend picker edits whichever row is currently selected — its `row`
    // defaults to the chart's selection, so there is no findIndex to keep in sync.
    legendColor({
      anchor: "right",
      edit: edit.legend.category(),
    }),
  ],
}))

Editing several rows at once

edit.select({ multi: true }) makes shift-click (or meta-click) add to the selection instead of replacing it; shift-clicking a selected row takes it back out. A plain click still replaces, so turning this on changes nothing about the gesture you already had.

A picker writes every selected row, so one swatch click recategorises the whole selection. Where the selected rows hold different values, each of those swatches is ringed.

From outside the chart, el.select([0, 2]) replaces the selection with those rows, el.toggleSelection(i) adds or removes one, el.selectAll() takes every row, and el.selectWhere('group', 'North', { all: true }) takes a whole category. el.getSelectionAll() reads them back.

Editing the category list

The pickers above write a row. edit.scale.categories() writes the domain — the list of categories itself — which is a property of the scale the legend draws, so it needs no target row at all.

It adds three affordances: double-click a swatch to rename its category, click the × to drop it, and double-click the + to add one. Renaming relabels every row carrying the old value, and removing deletes them, so the schema and the data never disagree.

The same edit works on an axis — axisX({ edit: edit.scale.categories() }) — because both draw a scale.

Where one scale spans several columns, every one is written — including columns in different tables. A category is one vocabulary however many columns share it, so renaming it in one table and not the other would split it in two.

A continuous value picker

Pass edit: edit.legend.value() to add a handle you drag along the ramp. A colour scale isn't invertible, so the edit maps the drag position back into the domain by hand and writes the value.

Drag the ramp to pick a value

Dragging the handle sets temp; the dot's colour tracks it.

mount(Elicit({
  width: 320, height: 210,
  margins: { top: 20, right: 16, bottom: 20, left: 20 },
  data: [ { temp: 15 } ],
  schema: { temp: { type: "quantitative", domain: [0, 30] } },
  axes: false,
  marks: [
    // The dot's colour tracks the elicited value as you drag the ramp handle.
    point({ size: 30, channels: { x: { value: 80 }, y: { value: 95 }, fill: { field: "temp" } } }),
    // edit.legend.value() adds a handle you drag along the ramp to set `temp`.
    // A colour scale isn't invertible, so the edit maps the drag to [0,30] by hand.
    legendColor({ anchor: "right", edit: edit.legend.value() }),
  ],
}))
Try: Drag the handle up and down the ramp to set the value.
