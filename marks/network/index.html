Network

A network is two tables — nodes and the links between them — declared with structure: "network". node() draws a labelled dot; link() draws one connector per link row, straight or curved, with arrowheads when directed. A ports channel on the node mark shows where links can meet a node. edit.network.connect, rewire and reverse build the topology; create, move, editText and remove work as on any other mark.

API reference

Declaring the structure

structure: "network" gives the dataset two tables in the roles nodes and links. The default "table" is one table — a bare field map, as on every other chart here.

schema: {
  structure: "network",
  tables: {
    nodes: {
      id: { type: "categorical", key: true, open: true },
      label: { type: "categorical", open: true },
      x: { type: "quantitative", domain: [0, 100] },
      y: { type: "quantitative", domain: [0, 100] },
    },
    links: {
      source: { type: "ref" },
      target: { type: "ref" },
      weight: { type: "quantitative", domain: [0, 1] },
    },
  },
}

key: true marks the column that identifies a node. type: "ref" marks a column that names one. Its domain is the key column's values.

Pair key with open: true so a gesture that mints a node can take a fresh identity.

data is keyed by table name. A table you leave out starts empty.

data: {
  nodes: [{ id: "a", label: "Ana", x: 20, y: 70 }],
  links: [],
}

getData(), onChange and setData use the same shape.

Nodes, no links

links: [] — the topology is drawn by gesture.

Kinds of network

Three flags on the links table say what its pairs mean. Declare them on the long form:

tables: {
  nodes: { fields: { … } },
  links: {
    directed: true,
    multi: true,
    selfLoops: true,
    fields: { source: { type: "ref" }, target: { type: "ref" } },
  },
}

directed and multi together give the four usual kinds of network:

kinddirectedmultione pair may have
graphfalse—one link
digraphtrue—one link each way
multigraphfalsetrueany number of links
multidigraphtruetrueany number, either way

selfLoops: true adds links from a node to itself to any of the four. See Parallel links and loops.

directed: true draws an arrowhead at the target, bows reciprocal links apart so a → b and b → a stay readable, and enables edit.network.reverse.

directed: false treats the pair as unordered: b → a is the same link as a → b.

Leave directed out and links draw without arrowheads. a → b and b → a are then two different links.

Directed links

directed: true — arrowheads, and a reciprocal pair that bows apart.

Parallel links and loops

multi: true lets connect and rewire add a link between two nodes that already share one. Links between the same two nodes fan apart (curvature: "auto").

selfLoops: true lets them link a node to itself. Drag from a port to another port of the same node, or move off the port and release on the node's body.

A link from a node to itself draws as a loop. It leaves and returns by one edge, or goes round the node from an out port to an in port. Further loops on one node take the free edges first, then nest outward. loopRadius sets how far a loop reaches (default 22).

Rows holding a parallel pair or a loop always draw. multi: false or selfLoops: false also logs a warning for them.

A state machine

directed, multi and selfLoops: two events from Open to Closed, and events that leave a state where it was.

Naming the tables

Name the tables for your data. Give each a role:

tables: {
  claims:   { role: "nodes", fields: { … } },
  supports: { role: "links", fields: { … } },
}

data and getData() are then keyed claims and supports. Marks and edits find their table by role, so link() draws supports by default. The argument map below is written that way.

Drawing a network

Any ordinary mark draws the nodes — point, rect, text, or a composite. Channels, scales and edits work as usual. A mark draws the nodes table by default; see which table a mark draws to point one at the links.

node() is the shorthand: a dot with a label above it. It takes x and y once for both, and draws the label from a text channel. It is a preset over composite and works on any table.

link() draws the links table. Each end sits at the node its ref column names.

Connector styles

curve sets a link's shape:

curveshape
"line"straight segment (the default)
"step"right-angled elbow, turning midway
"stepBefore" / "stepAfter"elbow turning at the source / at the target
"orthogonal"elbow that leaves each node square out of one of its edges
"arc"quadratic bow to one side
"bezier"cubic with square tangents; "smooth" is an alias

The "step" kinds turn on the straight line between two node positions. "orthogonal" leaves and arrives perpendicular to an edge of the node's shape — see where a link meets a node. cornerRadius rounds its turns (default 8; 0 is square).

Give curve a column to mix them in one mark:

link({ channels: { curve: { field: "kind" } } })

Any column works, or { fn: d => … } to map one. arrow reads a column the same way, so one field can drive both shape and arrowheads.

curvature sets how far a link bows; default "auto" fans links that share a pair of nodes and keeps a lone link straight. On a directed network every link bows to the same side of its travel, so a → b and b → a separate. Pass a number to bow every link equally, and spread to change the gap "auto" leaves between siblings.

Under "auto" a lone "arc" draws straight. A "line" with curvature draws as an arc, so links sharing a pair fan apart on a plain link().

A link whose source and target are the same node draws a loop — see Parallel links and loops.

A click edit like reverse or remove lands anywhere along the line.

Where a link meets a node

A link meets the shape the node mark draws: a dot's circle, a rect's edges, a sticker's paper. With no node mark, it ends at each node's position.

How an end meets the shape depends on whether the node has ports:

  • With ports, an end connects to a port. A pinned end uses the port on its side. An unpinned end uses the usable port facing the other node, and moves to another port when the nodes pass each other.
  • Without ports, an unpinned end slides. It sits where the line between the two centres leaves the shape, and moves smoothly as the nodes move. A pinned end sits at the middle of its edge.

inset is the connection buffer: how far from a node's shape a link stops, in px (default 0). sourceInset and targetInset set each end. An end at a port touches the port. An arrowhead fits in the gap.

An "orthogonal" connector leaves each end square to its edge and joins the two with the fewest turns. Two sliding ends nearly in line join with one straight leg; further apart they get a Z. It routes around a node in the way. Overlapping nodes get the plain route. A "line" or "bezier" connector meets the shape too, and a bezier leaves a pinned edge square-on.

sourceOffset and targetOffset move a pinned end along its edge, as a fraction from -0.4 to 0.4. Positive runs clockwise: right along the top, down the right, left along the bottom, up the left.

Notes without ports: one connector straightened, one detouring around a node, one taking the perpendicular edges.

Ports

A port is a dot on a node's edge where a link starts or ends. Declare ports with a ports channel on the mark that draws the nodes — any mark in What can be a node — and put edit.network.connect() on it:

sticker({
  channels: {
    x: { field: "x", edit: move({ channels: ["x", "y"], mode: "relative" }) },
    y: { field: "y" },
    text: { field: "label" },
    ports: {
      value: { out: ["right"], in: ["left"] },
      edit: edit.network.connect(),
    },
  },
})

The value says which edges a link may use. Use fn or field instead of value to vary it per node.

valueports
trueall four edges, either way
"right" or ["left", "right"]those edges, either way
{ out: ["right"], in: ["left"] }links leave by the right and arrive by the left (directed networks)
falsenone

Ports show where a link can go. Hover a node to see the ports a link can leave by. Start a drag and the ports that accept it light up. Both follow the out and in edges and the dataset's constraints.

Drag from a port and a dashed connector follows the pointer. Release on a port to connect there, or on a node's body to connect at its facing port. Release on empty space to cancel. Drag the body to move the node.

ports: true lets any edge connect to any edge, for a diagram you lay out freely.

Recording sides

To record which edge each end uses, name the columns on the link mark. Declare them in the links table as categorical over "top", "right", "bottom" and "left":

link({
  channels: {
    sourceSide: { field: "fromSide" },
    targetSide: { field: "toSide" },
  },
})

The gestures write those columns, and source/target to the link table's ref columns:

gesturethe links table
port to porta new row, with both sides
port to a node’s bodya new row; the target side is null
a link’s end to another nodethat row re-pointed, with its new side
a link’s end to empty spacethat row removed

A null side is unpinned. It meets the facing port, or slides along a node that has no ports. With no side channels, every end is unpinned.

edit.network.rewire() in the link mark's edits puts a handle on each end while you hover the connector. Drag one to another node to reconnect it, or into empty space to disconnect it. rewire({ channels: ["target"] }) handles one end only.

Constraints decide which ports show. Here each step shows an out port until it has one outgoing link.

Pinned sides

As options they set how links draw. Give one { fn: d => … } to derive a side from a column you already have.

What can be a node

Any mark that draws a shape at an x and a y can draw the nodes. Point it at the nodes table. Links meet the shape it draws, and a ports channel puts ports on that shape's edges:

marka link meets
point, nodethe dot's circle, or a square symbol's edges
ellipsethe ellipse, at rx and ry
rect, stickerthe box's edges
textthe box around the measured text, so an emoji or a word works
face, any composite placing parts in its boxthe box's circle
any other compositeits first part that draws a shape

A glyph puts ports on its main shape: the box's circle, or its first shape part. When a glyph draws a shape and a label, links meet the shape, so a node()'s links meet its dot. Links treat a rotated shape as unrotated.

Building the topology

Three gestures are network-specific; the rest is ordinary editing.

edit.network.connect() creates a link. Put it on a ports channel, or in the node mark's edits to drag from a node's body. On the body, give it and move different drags with when: connect({ when: when.shift }) beside move({ when: when.noShift }). With selfLoops: true, release on the node you started from to draw a loop. When the nodes draw no shape, a drop within threshold px of a node's centre connects.

edit.network.rewire() moves a link's ends — see Recording sides.

edit.network.reverse() on the link mark swaps the two ends on a click, keeping every other column. Give it a when if the mark carries another click edit. On directed: false it logs a warning and leaves the row as it is.

create() mints a node where you click. The node table's key gives it an identity, so you can link it straight away.

remove() deletes a node and every link to it.

Link attributes

A link row is a row like any other. Give the link table columns and encode them on link()'s style channels, or edit them with set, cycle and editText.

channels.text draws a label at the midpoint and takes editText() the same way a text mark does. Double-click anywhere along the connector to open the editor.

stroke and strokeWidth paint the connector and its arrowhead. fill paints the label (default: the theme's ink).

A label sits on its connector. labelBackground puts a plate behind it:

link({ labelBackground: true, channels: { text: { field: "note" } } })

true uses the theme's backdrop, which reads as a gap in the line; pass a colour string for anything else. labelOpacity (default 0.9) sets how much of the connector shows through; labelPadding and labelRadius size the plate.

Link attributes

A link's own columns drive its width, its colour and its label.

mount(Elicit({
  width: 460, height: 290,
  margins: { top: 24, right: 24, bottom: 24, left: 24 },
  axes: false,
  schema: {
    structure: "network",
    tables: {
      people: {
        role: "nodes",
        fields: {
          id: { type: "categorical", key: true, open: true },
          name: { type: "categorical", open: true },
          x: { type: "quantitative", domain: [0, 100] },
          y: { type: "quantitative", domain: [0, 100] },
        },
      },
      ties: {
        role: "links",
        fields: {
          source: { type: "ref" },
          target: { type: "ref" },
          note: { type: "categorical", open: true },
          trust: { type: "quantitative", domain: [0, 1] },
        },
      },
    },
  },
  data: {
    people: [
      { id: "a", name: "Ana", x: 18, y: 70 },
      { id: "b", name: "Ben", x: 80, y: 72 },
      { id: "c", name: "Cleo", x: 50, y: 20 },
    ],
    ties: [
      { source: "a", target: "b", note: "worked together", trust: 0.9 },
      { source: "b", target: "c", note: "met once", trust: 0.25 },

  },
  marks: [
    link({
      inset: 3,
      fontSize: 11,

      size: 10,

  ],
