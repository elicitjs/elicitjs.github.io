Axis, Grid & Rule

Axes and gridlines are chart elements — they draw a scale rather than the data. Prefer elicit.elements.* (or ElicitSpec.elements); the same factories stay aliased on plot.*. Configure them via the global axes: {…} convenience, or compose elements.axisX / gridY explicitly. ruleY is still a data mark.

API reference

axes (on Elicit)

The implicit layer. Every key desugars into the axis and grid marks below, and an explicit one you compose yourself always wins over the injected one.

axes: false                                  // no axes at all
axes: { x, y, count, origin }                // per-channel config
axes: { y: { grid: true, ticks: 8 } }        // any axis option
Options
OptionTypeDefaultDescription
x / yobject | false{}Options for that channel’s axis — any option in the table below. false suppresses the channel.
countboolean | objectfalseDraw the count axis of a counting mark (waffle, dotStack). It sits on whichever side that mark stacks along. Pass an object for the usual axis options.
originbooleanautoCross both axes at zero, instead of the left/bottom frame. Inferred true when a trend is present and you wrote no axes at all; state it either way to override.
Returns / emits

The injected axis / grid marks, in the background layer.

axis · axisX · axisY

A spine, ticks, labels and an optional title for one channel’s scale. Import from elicit.elements, or reach it through the axes option above.

rule · ruleX · ruleY

A straight reference line at a value on one axis — or, with a pair of endpoint channels, a span segment (a lollipop stem / error-bar whisker) at a category. An ordinary editable mark: put an edit on an endpoint channel and its cap becomes a handle. A rule with no edit is left pointerEvents:"none" by the engine, so an inert whisker never swallows a sibling handle’s drag.

ruleY({ channels: { y: { datum: 50 } } }) → Feature   // reference line at y = 50
ruleX({ channels: { x, y1, y2 } }) → Feature          // span per datum
Options
OptionTypeDefaultDescription
channelsobject{}The value channel — { datum } for a constant, { field } for one rule per row. y1/y2 or x1/x2 switch to span mode.
orientation'vertical' | 'horizontal'autoWhich axis carries the reference value ('vertical' = y). Inferred from the bound channel; ruleY / ruleX pin it.
editsEdit[]—As on any mark. A per-channel edit makes that endpoint draggable.
discreteScale'band' | 'point'—Which variant of a categorical axis the rule sits on. Left unset so a composite can stamp its own.
strokeDasharraystring—Dash pattern passthrough.
stroke, strokeWidth, opacitystylestroke:'black'Standard style surface.

Chart elements are not data marks

axis, grid, legend and axisRadial are public as elicit.elements.*. They still work inside marks and on plot.*, and you can separate them with elements: […] on the spec (concatenated into the feature list). See Mark & element contracts.

A data mark views the dataset's columns through a channels map. A chart element views one scale, named by a singular channel ('x', 'fill', 'angle'), so it has no data-mark channel map and no fields of its own. (axisRadial may carry optional x/y placement channels for per-row rings — placement chrome, not elicitation encoding.)

Its stroke, fill and fontSize paint a spine and its labels rather than a datum, so they stay plain options instead of becoming channels.

An edit on a data mark writes a row; an edit on a chart element writes the domain (edit.axis.*). create therefore doesn't apply to an element — there is no row to mint. Since an element has no channel map, an edit on one recovers its field from the scale, which is how a legend picker knows what to write.

A legend also reserves space, shrinking the plot; nothing else does.

Both halves have an implicit layer on the spec: axes for the positional scales, legends for the rest.

elicit.elements and ElicitSpec.elements

Prefer elements.axisX over treating axes as data marks. Pass chrome through elements: […] on the spec (or keep them in marks — same factories).

elements: […] with barY

axes: false, then explicit elements.axisX / axisY / gridY. The bar is the only data mark.

// Chart elements via elicit.elements + ElicitSpec.elements (also still work in marks).
mount(Elicit({
  width: 420, height: 220,
  schema: {
    cat: { type: 'categorical', domain: ['A', 'B', 'C'] },
    n: { type: 'quantitative', domain: [0, 100] },
  },
  data: [
    { cat: 'A', n: 40 },
    { cat: 'B', n: 70 },
    { cat: 'C', n: 55 },
  ],
  axes: false,
  elements: [
    elements.axisX({ ticks: 3, title: 'category' }),
    elements.axisY({ ticks: 4, title: 'n' }),
    elements.gridY(),
  ],
  marks: [
    barY({
      channels: {
        x: { field: 'cat' },
        y: { field: 'n', edit: move() },
      },
    }),
  ],
}));
Try: Drag a bar — the elements stay scale chrome.

The global axes:{} convenience

Pass a per-channel config to shape ticks, formats and titles, or a transform to reposition an axis. axes: false drops them entirely.

origin: true is the shorthand for crossing both axes at zero — declare it once instead of writing a transform on each channel by hand. It's the same frame trend/trendBand draw automatically; origin: false states the ordinary left/bottom frame explicitly on a chart that would otherwise infer the origin frame from its marks. A per-channel transform still covers anything origin doesn't — crossing at a value other than zero, or on one axis only.

Gridlines, ticks, format & title

y gets a grid and percent formatting; x a tick count and a title.

mount(Elicit({
  width: 380, height: 300,
  margins: { top: 16, right: 16, bottom: 30, left: 44 },
  axes: {
    x: { ticks: 4, title: "Funnel step" },
    y: { grid: true, tickFormat: ".0%", title: "Conversion" },
  },
  data: [
    { step: "Visit", rate: 1.0 }, { step: "Signup", rate: 0.62 },
    { step: "Active", rate: 0.41 }, { step: "Paid", rate: 0.18 },
  ],
  schema: {
    step: { type: "categorical", domain: ["Visit", "Signup", "Active", "Paid"] },
    rate: { type: "quantitative", domain: [0, 1] },
  },
  marks: [
    bar({
      channels: {
        x: { field: "step" },
        y: { field: "rate" },
      },
    }),
  ],
}))

Origin-crossing axes

axes: { origin: true } crosses both scales at zero, without a hand-written transform.

mount(Elicit({
  width: 360, height: 300,
  margins: { top: 16, right: 16, bottom: 24, left: 28 },
  axes: {
    origin: true,
    x: { ticks: 5 },
    y: { ticks: 5 },
  },
  data: [
    { x: -8, y: 6 }, { x: 5, y: -3 }, { x: -4, y: -7 },
    { x: 9, y: 4 }, { x: 2, y: 8 }, { x: -6, y: 2 },
  ],
  schema: {
    x: { type: "quantitative", domain: [-10, 10] },
    y: { type: "quantitative", domain: [-10, 10] },
  },
  marks: [
    point({
      size: 5, fill: "#4f46e5",
      channels: {
        x: { field: "x" },
        y: { field: "y" },
      },
    }),
  ],
}))

1D centred slider axis

One point channel; the axis is pinned to the vertical center via transform, and y is dropped.

mount(Elicit({
  width: 360, height: 200,
  margins: { top: 16, right: 20, bottom: 24, left: 20 },
  axes: {
    x: { transform: ({ height }) => ({ y: height / 2 }), ticks: 5, title: "Belief (0-100)" },
    y: false,   // drop the default y axis
  },
  data: [{ v: 20 }, { v: 55 }, { v: 80 }],
  schema: {
    v: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    point({
      size: 8, fill: "#0d9488",
      channels: {
        x: { field: "v" },
      },
      edits: [ move({ channels: ["x"] }) ],
    }),
  ],
}))
Try: Drag a dot along the axis.

Axis, grid & rule as marks

Turn the global axes off (axes: false) and compose reference marks into marks yourself — they render in z-order with your data, so you control exactly what draws and where.

Explicit gridY + axisX/axisY + ruleY

A gridline layer under the dots, a dashed rule at y = 50, and two titled axes — all as marks.

mount(Elicit({
  width: 380, height: 280,
  margins: { top: 16, right: 16, bottom: 30, left: 36 },
  axes: false,   // no auto axes; we place our own
  data: [{ x: 15, y: 30 }, { x: 40, y: 62 }, { x: 65, y: 44 }, { x: 88, y: 74 }],
  schema: {
    x: { type: "quantitative", domain: [0, 100] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    gridY({ ticks: 5 }),
    // `datum` is a DATA-space constant: it goes through the y scale, so the
    // line lands where y = 50 is. (`value` would mean 50 pixels.)
    ruleY({ channels: { y: { datum: 50 } }, stroke: "#e4572e", strokeDasharray: "4 3" }),
    point({
      fill: "#4f46e5",
      size: 8,
      channels: {
        x: { field: "x" },
        y: { field: "y" },
      },
    }),
    axisX({ title: "x", ticks: 5 }),
    axisY({ title: "y", ticks: 5 }),
  ],
}))
