Trend + Band

A parametric line and its uncertainty. The datum { intercept, slope } is a linear belief, and trend draws y = intercept + slope·x across the plot with a handle for each parameter: an intercept handle at x = 0 that translates the line, and a slope grip at each end that rotates it about the anchor. trendBand draws the band — a range on the intercept, a range on the slope, and every line between them.

API reference

Import from elicit.plot. A single-datum parametric line; the line itself is non-interactive and each handle is a draggable circle claimed by its own parameter.

edit.trend.*

The trend-scoped edits. Each inverts the pointer through x/y and solves for the parameter it owns, writing the column that parameter’s channel names. A pinned parameter is never written.

An Edit with scope: "trend", claiming the handle tagged with its own channel. trend() generates the first two for you; declare them yourself to restage them, retarget them, or drive them from the plane.

Its channels name the axes, not the columns

Trend is the one mark whose x and y channels name the plot's axes rather than columns of its datum. Declare their domains in the schema, typically spanning negatives so the intercept sits in the middle of the frame.

Left unspecified, axes crosses at the origin when a trend is present. State the frame explicitly with axes: { origin: true | false } — see Axis, Grid & Rule.

Trend can't be created by a gesture

Unlike a point or bar, a trend line is derived: its position comes from intercept/slope, not from an x/y you could invert a click into. So a plane create has nothing to place — trend is one of the two exceptions (with guides) in the can/can't-create matrix. You author a trend by editing its parameters, not by adding rows.

Inert until an edit names the column

trend() draws the line and both handles, and writes nothing. Like every other mark, it is a view until an edit says which column a gesture sets — edit.trend.intercept() on the intercept channel, edit.trend.slope() on the slope channel. Staging goes on the edit (edit.trend.slope({ stage: 1 })), the same way it does everywhere else.

No edit, no writes

The handles are drawn but the data never moves.

mount(Elicit({
  width: 360, height: 260,
  margins: { top: 16, right: 16, bottom: 28, left: 34 },
  schema: {
    x: { type: "quantitative", domain: [-10, 10] },
    y: { type: "quantitative", domain: [-10, 10] },
    intercept: { type: "quantitative" },
    slope:     { type: "quantitative" },
  },
  data: [{ intercept: 2, slope: 0.5 }],
  marks: [
    // No edit anywhere: the line and both handles draw, and nothing you do to
    // them changes the data. A mark is a VIEW until an edit names the column a
    // gesture writes — trend is no exception, and used to be.
    trend({
      channels: {
        intercept: { field: "intercept" },
        slope:     { field: "slope" },
      },
    }),
  ],
}));
Try: drag either dot — nothing changes.

Intercept, then slope

Domains span both sides of zero so the intercept sits on the y-axis in the middle of the frame. Stage 0: drag the intercept handle to set the level. Stage 1: drag either end grip to set the trend, rotating about the anchor.

The parameters are channels like any other, so the columns are renameable — channels: { slope: { field: "r" } } — or pinnable to a constant with { datum }. They are unscaled: parameters in their own units, projected through x/y rather than encoded themselves.

That default is an inference, not a fixed rule: it only applies while axes is left unspecified. State the frame instead of relying on it — axes: { origin: false } forces the ordinary left/bottom frame even with a trend mark on the chart.

axes only moves the axis spines; it says nothing about where the handles sit. Those follow anchor/probe, which default for the origin-crossing frame (anchor is 0 whenever 0 lies in the x domain). Over a domain that doesn't need to cross zero, that same default places anchor at the domain's own start — exactly where a left/bottom y-axis is drawn — so the intercept handle lands on the axis instead of floating mid-plot. Pair it with grip: "probe" for a single slope handle at the domain's far end, rather than the default pair, whose near-end grip would otherwise sit on top of the intercept handle.

Trend line

Axes cross at the origin automatically; the line runs edge-to-edge through the plot.

const chart = Elicit({
  width: 360, height: 300,
  margins: { top: 16, right: 16, bottom: 28, left: 34 },
  schema: {
    x: { type: "quantitative", domain: [-10, 10] },
    y: { type: "quantitative", domain: [-10, 10] },
    intercept: { type: "quantitative" },
    slope:     { type: "quantitative" },
  },
  data: [{ intercept: 0, slope: 0.6 }],
  marks: [
    // A trend draws its line and two handles, but writes nothing until an edit
    // names the column each handle sets. Staging goes on the edit, like any other:
    // the intercept is live in stage 0, the slope in stage 1.
    trend({
      channels: {
        intercept: { field: "intercept", edit: edit.trend.intercept({ stage: 0 }) },
        slope:     { field: "slope",     edit: edit.trend.slope({ stage: 1 }) },
      },
    }),
  ],
});

Both handles at once

Omit the stages (default null) to leave both handles always active.

mount(Elicit({
  width: 360, height: 300,

  schema: {
    x: { type: "quantitative", domain: [-10, 10] },
    y: { type: "quantitative", domain: [-10, 10] },

    // Unstaged: both handles live at once. Each edit claims its own handle, so
    // dragging the intercept never moves the slope and vice versa.
    trend({
      channels: {

        slope:     { field: "slope",     edit: edit.trend.slope() },

Left/bottom frame

axes: { origin: false }, plus a domain starting at 0 and grip: "probe" — the intercept handle sits on the y-axis, the one slope handle on the right edge.

mount(Elicit({
  width: 360, height: 300,
  margins: { top: 16, right: 16, bottom: 28, left: 34 },
  // Without this, axes here would still cross at zero — a trend mark is
  // present and axes was otherwise unspecified. origin: false states the
  // ordinary left/bottom frame explicitly instead of leaving it inferred.
  axes: { origin: false },
  schema: {
    // A domain that doesn't need to span negative values, so trend's default
    // anchor (0, whenever 0 lies in the x domain — here that's the domain's
    // own start) lands exactly where the y-axis is drawn, instead of
    // floating mid-plot the way it would over a domain like [-10, 10].
    x: { type: "quantitative", domain: [0, 20] },
    y: { type: "quantitative", domain: [0, 20] },
    intercept: { type: "quantitative" },
    slope:     { type: "quantitative" },
  },
  data: [{ intercept: 2, slope: 0.5 }],
  marks: [
    trend({
      // grip: "probe" mounts a single slope handle at the domain's far end.
      // The default pair (grip: "end") would put its near-end grip on the
      // same point as the intercept handle now that anchor sits at x = 0.
      grip: "probe",
      channels: {
        intercept: { field: "intercept", edit: edit.trend.intercept() },
        slope:     { field: "slope",     edit: edit.trend.slope() },
      },
    }),
  ],
}));

Rotating the line

The slope grips sit on the line’s own ends, and dragging one passes the line through the pointer. So the line rotates a full turn: drag an end up and over the anchor and the line swings past vertical and comes down the other side. Both ends carry the same edit, and each stays inside the plot at every angle.

A vertical line has no slope. The gesture holds while the pointer is in the anchor’s own column, and slope grows without bound as you approach it — bound it with a clamp on the column, the same way you would bound any other field.

grip: "probe" pins a single grip at x = probe instead, sliding vertically at that column. Reachable slope is then capped at ySpan / (probe − anchor).

Swing it round

Both parameters live, with slope clamped to ±20.

const chart = Elicit({
  width: 340, height: 300,
  margins: { top: 16, right: 16, bottom: 28, left: 40 },
  schema: {
    x: { type: "quantitative", domain: [-10, 10] },
    y: { type: "quantitative", domain: [-10, 10] },
    intercept: { type: "quantitative" },
    slope:     { type: "quantitative" },
  },
  data: [{ intercept: 0, slope: 0.6 }],
  // The slope grows without bound as the line approaches vertical. Bound it the
  // same way you bound any other column.
  constraints: [clamp({ field: "slope", min: -20, max: 20 })],
  marks: [
    trend({
      channels: {
        intercept: { field: "intercept", edit: edit.trend.intercept() },
        slope:     { field: "slope",     edit: edit.trend.slope() },
      },
    }),
  ],
});

The band around the line

trendBand takes the same two parameters plus a spread on each: interceptSpread and slopeSpread, half-widths in the field’s own units. The band it draws is the whole family of lines those ranges allow, and its envelope is exact — piecewise linear, with a single kink where x crosses zero (the point where only the intercept range is left).

The two marks are views of one dataset. trendBand declares no edits of its own: a whole-dataset gesture declared on two marks would run twice, so put the edit on the mark the reader grabs and let the other re-derive on the next render.

For an asymmetric band, name the ends instead: intercept1/intercept2 and slope1/slope2, the same 1/2 span spelling area and rect use. The range form wins wherever both are declared; pair it with ordering to stop it turning inside out.

A band around the line

Every line whose intercept is within aSd and whose slope is within bSd.

mount(Elicit({
  width: 360, height: 300,
  margins: { top: 16, right: 16, bottom: 28, left: 34 },
  schema: {
    x: { type: "quantitative", domain: [-10, 10] },
    y: { type: "quantitative", domain: [-10, 10] },
    // The band's four elicited columns. Every column of the dataset belongs in
    // the schema — that is the contract of what this chart elicits.
    intercept: { type: "quantitative" },
    slope:     { type: "quantitative" },
    aSd:       { type: "quantitative" },
    bSd:       { type: "quantitative" },
  },
  data: [{ intercept: 1, slope: 0.4, aSd: 1.5, bSd: 0.25 }],
  marks: [
    trendBand({
      fill: "#2563eb",
      channels: {
        interceptSpread: { field: "aSd" },
        slopeSpread:     { field: "bSd" },
      },
    }),
    // Drag either handle to move the line; the band above re-derives from the same
    // two parameters, so it follows without carrying an edit of its own.
    trend({
      stroke: "#2563eb",
      channels: {
        intercept: { field: "intercept", edit: edit.trend.intercept() },
        slope:     { field: "slope",     edit: edit.trend.slope() },
      },
    }),
  ],
}));

Three readings of one band

render picks how the same family is drawn. region (the default) is one polygon: the exact envelope. gradient stacks levels nested envelopes so the ink darkens toward the line. samples draws individual lines from the family — the ensemble reading, where you see the hypotheses rather than their hull. There distribution chooses normal (the bounds are a sigma-wide envelope, so ~95% of draws land inside them) or uniform (every line in the range equally plausible).

Each render inks through its own ordinary style channel: fillOpacity (default 0.18) for the filled forms, strokeOpacity (default 0.15) for one line of the fan. So a fan gets denser as you raise samples — drop strokeOpacity to thin it back out, or raise it for a sparse one.

region, gradient, samples

One belief, three renderings. The polygon and the fan are the same statement.

const belief = [{ intercept: 1, slope: 0.4, aSd: 1.5, bSd: 0.25 }];
const spreads = { interceptSpread: { field: "aSd" }, slopeSpread: { field: "bSd" } };
const lineParams = {
  intercept: { field: "intercept", edit: edit.trend.intercept() },
  slope:     { field: "slope",     edit: edit.trend.slope() },
};

for (const render of ["region", "gradient", "samples"]) {
  mount(Elicit({
    width: 200, height: 170,
    margins: { top: 10, right: 10, bottom: 22, left: 26 },
    schema: {
      x: { type: "quantitative", domain: [-10, 10] },
      y: { type: "quantitative", domain: [-10, 10] },
      intercept: { type: "quantitative" },
      slope:     { type: "quantitative" },
      aSd:       { type: "quantitative" },
      bSd:       { type: "quantitative" },
    },
    data: belief,
    marks: [
      trendBand({ render, levels: 6, samples: 80, fill: "#0f766e", stroke: "#0f766e", channels: spreads }),
      // Three renderings of the SAME belief, so all three share one edit set.
      trend({ stroke: "#0f766e", channels: lineParams }),
    ],
  }));
}

A correlation is a pinned trend

A correlation belief is this mark with two things said about it: the intercept is pinned at the origin, and the slope is a coefficient in [-1, 1]. Neither needs a mark of its own — pinning is a constant channel (intercept: { datum: 0 }, which names no column, so no edit can write one), and the range is a clamp.

Stage 0 aims the line: under probe there is no handle to grab, so the gesture takes the pointer’s own x and the line follows the cursor; a click sets it and advances. Stage 1 opens the band — slopeSpread is how far the line through the pointer tilts away from the committed one, so the edge of the fan sits under the cursor.

Both axes span matched [-1, 1] domains over a square plot, which is what makes the line’s screen angle read as r. Shipped as widgets.lineCone.

Line + Cone, from the general marks

Two clicks: aim the line, then open the cone.

const chart = Elicit({
  width: 300, height: 300,
  margins: { top: 14, right: 14, bottom: 14, left: 14 },
  axes: false,
  schema: {
    // Standardized units, matched on both axes, so a slope of 1 is a 45° line.
    x: { type: "quantitative", domain: [-1, 1] },
    y: { type: "quantitative", domain: [-1, 1] },
    r:      { type: "quantitative", domain: [-1, 1], default: 0 },
    spread: { type: "quantitative", domain: [0, 1],  default: 0 },
  },
  data: [{ r: 0, spread: 0 }],
  // What makes it a CORRELATION rather than a free trend — declared, not baked in.
  constraints: [
    clamp({ field: "r",      min: -1, max: 1 }),
    clamp({ field: "spread", min: 0,  max: 1 }),
  ],
  marks: [
    trendBand({
      render: "samples",
      samples: 80,
      channels: {
        intercept:   { datum: 0 },       // pinned at the origin
        slope:       { field: "r" },
        slopeSpread: { field: "spread" },
      },
    }),
    trend({
      handles: false,
      stroke: "#f59e0b",
      strokeWidth: 5,
      channels: {
        intercept: { datum: 0 },
        slope:       { field: "r",      edit: edit.trend.slope({ pick: "probe", stage: 0 }) },
        slopeSpread: { field: "spread", edit: edit.trend.slopeSpread({ pick: "probe", stage: 1 }) },
      },
    }),
  ],
});
mount(chart);
const out = document.createElement("div");
out.style.cssText = "font:12px ui-monospace,monospace;margin-top:6px;color:#64748b";
const show = () => {
  const d = chart.getData()[0] || {};
  out.textContent = "stage " + chart.getStage() +
    "  ·  r=" + (d.r ?? 0).toFixed(2) + "  spread=" + (d.spread ?? 0).toFixed(2);
};
chart.on("change", show); chart.on("stage", show); show();
mount(out);
