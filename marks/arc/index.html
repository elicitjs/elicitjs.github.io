Arc · Pie · Donut

Data-driven pie and donut slices. Each row’s magnitude (the theta channel) is stacked and normalized to a circle (or partial arc). Shares path math with axisRadial. Wire edits: [edit.stack.edge()] to drag a slice boundary and redistribute the two adjacent shares (the total stays fixed).

API reference

arc(options) · donut(options)

Import from elicit.plot. donut is arc with a default inner radius. A full pie is just arc().

donut(options) → Feature

Channels
ChannelTypeDescription
thetamagnitude fieldSlice size in data units; layout normalizes by the sum of rows. The polar positional channel (Vega-Lite's name for it) — not `angle`, which is a mark's rotation in place, and not `value`, which already means a visual-space constant on any channel. A feature emitting one filled path per row.

Pie

Full circle, zero inner radius.

Party shares

Three slices from a shared total.

mount(Elicit({
  width: 300, height: 280,
  margins: { top: 20, right: 20, bottom: 20, left: 20 },
  axes: false,
  data: [
    { party: "D", share: 48 },
    { party: "R", share: 45 },
    { party: "O", share: 7 },
  ],
  schema: {
    party: { type: "categorical" },
    share: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    arc({
      outerRadius: 100,
      channels: {
        theta: { field: "share" },
        fill: { field: "party" },
      },
    }),
  ],
}));

      fontSize: 22,

        text: { value: "100%" },
        textAnchor: { value: "middle" },
        lineAnchor: { value: "middle" },
      },
    }),
  ],
}));

Editable slice boundaries

Wire edit.stack.edge() and every interior boundary gets a draggable handle, so n slices give n − 1 handles. The seam where the last slice meets the first is the layout's fixed anchor: with the orientation and the total both fixed, those n − 1 boundaries are all that can move independently.

Dragging one moves value between exactly the two slices it separates. One grows by what the other loses, so the total is preserved.

Drag any boundary

Each handle pair-shifts the two slices it sits between; the rest of the pie holds still.

mount(Elicit({
  width: 300, height: 280,
  margins: { top: 20, right: 20, bottom: 20, left: 20 },
  axes: false,
  data: [
    { party: "D", share: 40 },
    { party: "R", share: 35 },
    { party: "O", share: 25 },
  ],
  schema: {
    party: { type: "categorical" },
    share: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    arc({
      outerRadius: 100,
      edits: [edit.stack.edge()],
      channels: {
        theta: { field: "share" },
        fill: { field: "party" },
      },
    }),
  ],
}));
Try: Drag a dot on any slice edge.

Donut, four slices

Four slices → three handles.

mount(Elicit({
  width: 300, height: 280,
  margins: { top: 20, right: 20, bottom: 20, left: 20 },
  axes: false,
  data: [
    { cat: "A", v: 20 },
    { cat: "B", v: 20 },
    { cat: "C", v: 20 },
    { cat: "D", v: 40 },
  ],
  schema: {
    cat: { type: "categorical" },
    v: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    donut({
      outerRadius: 100, innerRadius: 50,
      edits: [edit.stack.edge()],
      handleSize: 6,
      channels: {
        theta: { field: "v" },
        fill: { field: "cat", scale: { scheme: "tableau10" } },
      },
    }),
  ],
}));
Try: Drag any edge — the two adjacent slices rebalance.

Cutting and merging slices

A pie divides one total among its rows, which is what a stacked bar does along an axis — so the same three gestures work on both:

  • edit.stack.cut() — click inside a slice to divide it in two at the pointer angle.
  • edit.stack.edge() — drag a boundary to move value across it.
  • edit.stack.merge() — double-click a boundary to fuse those two slices back into one.

Each preserves the pie's total. A cut takes its category from the schema's domain, so it needs no typing: a closed domain hands out the values this pie doesn't yet use and refuses the cut once they run out, while open: true lets each cut append a new one. See Slicing a stack for the bar form.

Cut a slice

One full circle to start. The category domain declares five values, so the pie takes four cuts.

mount(Elicit({
  width: 300, height: 300,
  margins: { top: 20, right: 20, bottom: 20, left: 20 },
  axes: false,
  data: [{ category: "housing", share: 100 }],
  schema: {
    category: {
      type: "categorical",
      domain: ["housing", "food", "transport", "savings", "other"],
    },
    share: { type: "quantitative", domain: [0, 100] },
  },
  legends: true,
  marks: [
    arc({
      outerRadius: 100,
      channels: {
        theta: { field: "share" },
        fill: { field: "category" },
      },
      edits: [
        edit.stack.cut(),
        edit.stack.edge(),
        edit.stack.merge(),
      ],
    }),
  ],
}));
Try: Click inside a slice to cut it, drag a boundary to shift share, double-click one to merge.

A grid of donuts

A donut is a view over a group of rows the way a face is a view over one row — so it scatters into the plane the same way. Bind x (and optionally y) to a field and each distinct value becomes a slot holding its own donut; the rows at that slot are its slices. There is no group transform — the encoding is the grouping. (A size field scales each donut independently; outerRadius pins one radius for all; otherwise the radius fits the slot.)

Here x: { field: 'state' } gives a band axis, so IL / NY / NC each get a donut of their own party split. A boundary drag redistributes share within that state only — the per-slot sum a pie holds by construction — and never disturbs another state.

Party split per state

One donut per band-axis category; each state's boundaries redistribute within that state alone.

mount(Elicit({
  width: 520, height: 260,
  margins: { top: 20, right: 20, bottom: 30, left: 20 },
  data: [
    { state: "IL", party: "D", share: 55 },
    { state: "IL", party: "R", share: 38 },
    { state: "IL", party: "O", share: 7 },
    { state: "NY", party: "D", share: 60 },
    { state: "NY", party: "R", share: 33 },
    { state: "NY", party: "O", share: 7 },
    { state: "NC", party: "D", share: 47 },
    { state: "NC", party: "R", share: 48 },
    { state: "NC", party: "O", share: 5 },
  ],
  schema: {
    party: { type: "categorical" },
    share: { type: "quantitative", domain: [0, 100] },
    state: { type: "categorical", domain: ["IL", "NY", "NC"] },
  },
  marks: [
    donut({
      edits: [edit.stack.edge()],
      handleSize: 6,
      channels: {
        x: { field: "state" },          // band axis → one donut per state
        theta: { field: "share" },      // party's share within its state
        fill: { field: "party" },
      },
    }),
  ],
}));
Try: Drag a boundary in one state — only that state’s shares rebalance.
