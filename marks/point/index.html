Point

point is the channel-driven scatter mark: every channel — x, y, size, fill, stroke, angle — resolves through the global scales. Default shape is a circle; shape: 'square' emits a centred rect (side 2 × size) that can rotate about its centre.

API reference

point(options)

Import from elicit.plot. A circle or square per datum; every channel — positional or not — resolves through the global scales.

editsEdit[]—Mark-level edits; per-channel edits live in the channels map.

A feature emitting one circle or rect per datum.

Channels: size, fill, colour

A numeric field can drive the radius (size) and a continuous colour ramp at once; a categorical field drives the ordinal palette. Constants and fields mix freely on the same mark.

Sequential fill + size from a number

A numeric field drives both the continuous colour ramp and the radius.

mount(Elicit({
  width: 340, height: 240,
  margins: { top: 14, right: 14, bottom: 26, left: 34 },
  data: [
    { h: 150, weight: 48 }, { h: 160, weight: 57 }, { h: 170, weight: 66 },
    { h: 180, weight: 78 }, { h: 190, weight: 92 }, { h: 165, weight: 61 },
  ],
  schema: {
    h:      { type: "quantitative", domain: [140, 200] },
    weight: { type: "quantitative", domain: [40, 100] },
  },
  marks: [
    point({
      stroke: "#334155", strokeWidth: 1,
      channels: {
        x: { field: "h" },
        y: { field: "weight" },
        fill: { field: "weight" },   // number -> sequential ramp
        size: { field: "weight" },   // number -> radius
      },
    }),
  ],
}))

Heatmap of circles / squares

Put a category on both x and y and each dot centres at that intersection — a grid heatmap. fill encodes the value as colour and size as radius, so magnitude reads twice; shape: 'square' swaps circles for centred squares. Reach for rect instead when you want filled cells that tile the plane. The size scale is invertible, so resize() on it drags a dot's radius back to a value — its colour re-derives from the same field.

Sized, coloured grid

Category on x and y; size and fill both ramp off the value field.

mount(Elicit({
  width: 420, height: 260,
  margins: { top: 16, right: 84, bottom: 30, left: 56 },
  data: [
    { day: "Mon", slot: "AM", load: 4 },  { day: "Mon", slot: "PM", load: 9 },  { day: "Mon", slot: "Eve", load: 6 },
    { day: "Tue", slot: "AM", load: 7 },  { day: "Tue", slot: "PM", load: 14 }, { day: "Tue", slot: "Eve", load: 8 },
    { day: "Wed", slot: "AM", load: 12 }, { day: "Wed", slot: "PM", load: 20 }, { day: "Wed", slot: "Eve", load: 11 },
    { day: "Thu", slot: "AM", load: 6 },  { day: "Thu", slot: "PM", load: 16 }, { day: "Thu", slot: "Eve", load: 10 },
  ],
  schema: {
    day:  { type: "categorical", domain: ["Mon", "Tue", "Wed", "Thu"] },
    slot: { type: "categorical", domain: ["AM", "PM", "Eve"] },
    load: { type: "quantitative", domain: [0, 20] },
  },
  marks: [
    // A category on both axes centres one dot per (day, slot). `size` ramps the
    // radius and `fill` the colour off the same field, so magnitude reads twice.
    // `size` is invertible, so resize() drags a dot's radius back to a value —
    // its colour re-derives from the same field on the next render.
    point({
      channels: {
        x:    { field: "day" },
        y:    { field: "slot" },
        size: { field: "load", edit: edit.resize() },
        fill: { field: "load" },
      },
    }),
    legendColor({ anchor: "right", title: "load" }),
  ],
}))
Try: Drag a dot to resize it and set its value.

Moving points in 2D

When both x and y carry a drag, a gesture inverts the pointer through both positional scales.

2D move (scatter)

Both x and y carry edit: move(), so a dot moves anywhere.

mount(Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: [{ x: 20, y: 30 }, { x: 50, y: 62 }, { x: 78, y: 40 }],
  schema: {
    x: { type: "quantitative", domain: [0, 100] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    point({
      fill: "#2563eb", stroke: "#1f2733", strokeWidth: 1, opacity: 0.85,
      size: 9,
      channels: {
        x: { field: "x" },
        y: { field: "y" },
      },
      edits: [ move({ channels: ["x", "y"] }) ],
    }),
  ],
}))
Try: Drag a dot anywhere.

Adding points

point is the canonical creatable mark: a plane gesture inverts the pointer through the x and y scales to mint a datum, exactly the inverse of how those channels encode it. Because a move-drag lives on the same mark here, the creator uses gesture: "dblclick" so it doesn't race the drag. See Create · Remove · Anchors for the full model and the can/can't-create matrix.

Double-click to add a point

create({ gesture: "dblclick" }) mints a datum at the pointer; group comes from the schema default; count({ max }) caps the dataset.

mount(Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: [
    { x: 25, y: 40, group: "a" },
    { x: 60, y: 70, group: "a" },
  ],
  schema: {
    x: { type: "quantitative", domain: [0, 100] },
    y: { type: "quantitative", domain: [0, 100] },
    group: { type: "categorical", default: "a" },
  },
  constraints: [ count({ max: 10 }) ],
  marks: [
    point({
      fill: "#0d9488",
      size: 8,
      channels: {
        x: { field: "x", edit: move() },
        y: { field: "y", edit: move() },
      },
      // dblclick, not click: a plain click would race the move-drag on the same
      // mark. The pointer inverts through x and y to mint the datum; group comes
      // from the schema default. count caps the dataset.
      edits: [ create({ gesture: "dblclick" }) ],
    }),
  ],
}))
Try: Double-click empty space to add a point · drag to move it.

Rotating squares and ticks

An angle channel orients a mark about its centre. Degrees are math convention (0° = +x, counterclockwise); rotate() inverts the pointer through the same scale. Squares use point({ shape: 'square' }); short tickX / tickY segments (with length) rotate the same way — useful for directional markers on a scatter.

Rotation is a transform, not a change of geometry: the mark keeps its upright coordinates and the renderer spins it about its centre. Everything that answers the pointer follows that transform — proximity picking measures the tick where it is drawn, and an interaction effect (a hover or selection outline) turns with the mark it belongs to.

Scatter of rotatable squares

shape: 'square' plus angle with rotate({ pivot: 'mark', fold: false, pick: 'direct' }).

mount(Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: [
    { x: 20, y: 30, theta: -20 },
    { x: 50, y: 62, theta: 35 },
    { x: 78, y: 40, theta: 70 },
    { x: 35, y: 75, theta: -55 },
  ],
  schema: {
    x:     { type: "quantitative", domain: [0, 100] },
    y:     { type: "quantitative", domain: [0, 100] },
    theta: { type: "quantitative", domain: [-180, 180] },
  },
  marks: [
    point({
      shape: "square",
      fill: "#2563eb", stroke: "#1e3a8a", strokeWidth: 1, size: 10,
      channels: {
        x: { field: "x" },
        y: { field: "y" },
        angle: {
          field: "theta",
          scale: { range: [-180, 180] },
          edit: rotate({ pivot: "mark", fold: false, pick: "direct" }),
        },
      },
    }),
  ],
}))
Try: Drag a square to spin it.

Grabbing a spun tick from nearby

pick: 'nearest' with a 12px threshold. The catchment tracks each tick's drawn arm, so the flat one is grabbable along the horizontal.

mount(Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: [
    { x: 22, y: 32, theta: 90 },
    { x: 74, y: 68, theta: 20 },
  ],
  schema: {
    x:     { type: "quantitative", domain: [0, 100] },
    y:     { type: "quantitative", domain: [0, 100] },
    theta: { type: "quantitative", domain: [-180, 180] },
  },
  marks: [
    tickX({
      length: 36,
      stroke: "#1d4ed8",
      strokeWidth: 4,
      channels: {
        x: { field: "x" },
        // A 4px tick is a small target, so pick the nearest one within 12px
        // instead of demanding a hit. The catchment is measured against the tick
        // as DRAWN — along the arm it currently points down, not the vertical it
        // would occupy at 0° — so the left tick (spun flat) is grabbable off
        // either END, nowhere near the upright segment it started as.
        y: {
          field: "y",
          edit: move({
            channels: ["y"],
            pick: "nearest",
            threshold: 12,
            guide: { catchment: true },
          }),
        },
        angle: { field: "theta", scale: { range: [-180, 180] } },
      },
    }),
  ],
}))
Try: Drag from just off either tick — including off the END of the flat one, well away from the vertical it would sit on at 0°.
