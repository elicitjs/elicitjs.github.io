Guides

A guide draws the rule and the state — what a gesture is allowed to do, and what is left to do. It views chart state rather than rows, so it has no channels, no table and no edit, and can never write data. Declare one in guides: [...] (guides.rule, guides.region, guides.remaining, guides.proximity, guides.custom), or let an edit draw its own with guide:. Guides rebuild every render and never capture a gesture. For feedback on interaction state — hovered, selected, grabbed — see Effects.

API reference

guides.rule · guides.region · guides.remaining · guides.proximity

Import from elicit.guides and pass in the chart’s guides: [...]. All position in data space through the same scale.encode() a mark uses, so they compose across scale types. Non-interactive.

guides.rule({ x?, y?, label, stroke, strokeDasharray, strokeWidth, opacity }) → Guide
guides.region({ x?, y?, fill, opacity }) → Guide
guides.remaining({ field, total?, unit?, format?, anchor?, label?, fill?, fontSize? }) → Guide
guides.proximity({ target, stroke, strokeDasharray, strokeWidth, opacity }) → Guide
guides.custom((ctx) => FeatureNode[]) → Guide

guides.rule({ y: ({ data }) => d3.mean(data, (d) => d.y), label: "mean" })

Instrument affordances

The chrome a survey instrument draws itself with. Guides like any other — pass them in guides: [...]. The built-in widgets are assembled from these, so a hand-built instrument gets the same look.

guides.prompt(text, { y }) → Guide            // the question, in the top margin
guides.optionRings({ labelOffset, radius }) → Guide   // a Likert scale's rings
guides.cellGrid({ pad }) → Guide              // a matrix's cells + headers
guides.sliderTrack({ format }) → Guide        // a track with end labels
guides.crosshair({ x, y }) → Guide            // centred axes + four end labels

guide (on an edit)

What an edit draws about its own rules. guide: true turns on bounds and catchment at their defaults; an object turns parts on individually and restyles them.

guide: true | false | { bounds, catchment, track, color }
Options
OptionTypeDefaultDescription
boundsboolean | objecton with guide: trueConstraint boundaries on the edit's own value channel — a clamp's band and limit lines, a snap's stops, a maintainSum cap.
catchmentboolean | objecton with guide: trueThe reach of a proximity pick: the radius within which a free pointer resolves to a mark. Only drawn by picks that select one.
trackboolean | objectoffWhere a handle can travel. Opt-in: extra ink on a chart that already shows the handle, and worth it when the range isn't obvious.
colorstringtheme.constraint.colorOne colour for every part; a part's own colour still wins.
<part>.dash · width · opacityany—Per-part stroke appearance.

Which kind you want

The two differ in who declares them.

guide: on an edit draws the edit's own rules. It already knows the channel, the scale and the constraints that gate it, so you repeat none of them. Use it to show what a gesture is allowed to do.

guides: [...] on the spec draws an annotation you choose — a target line, a shaded range — from whatever you compute out of the guide context.

Reach for the edit-owned form when the thing you want to draw is already known to the edit. A guides.rule at a clamp limit restates that limit in two places, and the two drift apart.

An edit draws its own rules

guide: true on an edit turns on bounds and catchment. You repeat nothing from the constraints: the edit draws every dataset constraint whose field matches its own channel.

Bounds follow the edit's axis. The same clamp draws horizontal lines on a y-edit and vertical ones on an x-edit.

clamp and snap, drawn by the edit

guide: true draws the allowed band and a labelled line at each clamp limit.

mount(Elicit({
  width: 400, height: 260,
  margins: { top: 16, right: 16, bottom: 28, left: 36 },
  data: [{ cat: "A", n: 55 }, { cat: "B", n: 30 }, { cat: "C", n: 70 }],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C"] },
    n:   { type: "quantitative", domain: [0, 100] },
  },
  // The rules this chart enforces. An edit governed by them can draw them.
  constraints: [ clamp({ field: "n", min: 20, max: 85 }) ],
  marks: [
    bar({
      channels: {
        x: { field: "cat" },
        // `guide: true` turns on bounds and catchment. This edit has no proximity
        // pick, so only the bounds draw: the allowed band and a labelled line at
        // each `clamp` limit. You repeat none of it — the edit draws every
        // constraint whose `field` matches its channel.
        y: { field: "n", edit: move({ guide: true }) },
      },
    }),
  ],
}))
Try: Drag a bar past a limit, or between the snap stops.

What is left to do

guides.remaining() states how much of a budget is still unallocated — the count a reader needs while placing tokens or splitting a total.

guides.remaining({ field: "y", unit: "token" })   // "3 tokens left"
guides.remaining({ field: "y", total: 100 })      // "45 of 100 left"

Pass no total and it reads the target from the chart's own maintainSum constraint, so the number you enforce and the number you show cannot drift apart. Set unit for the countable phrasing, anchor ("top-right" by default) for the corner, and label for a function of (remaining, used, total) when you want your own wording.

A budget with its remainder

guides.remaining reads the target from the maintainSum constraint, so the budget is written once.

mount(Elicit({
  width: 380, height: 260,
  margins: { top: 26, right: 14, bottom: 26, left: 34 },
  // No `total` here: the guide reads the target off the maintainSum
  // constraint, so the budget is written once.
  guides: [ guides.remaining({ field: "y", unit: "point" }) ],
  data: [
    { x: "A", y: 25 }, { x: "B", y: 20 },
    { x: "C", y: 15 }, { x: "D", y: 10 },
  ],
  schema: {
    x: { type: "categorical", domain: ["A", "B", "C", "D"] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  constraints: [ clamp({ min: 0 }), maintainSum({ total: 100, strategy: "cap" }) ],
  marks: [
    barY({
      fill: "#7c3aed",
      channels: {
        x: { field: "x" },
        y: { field: "y", edit: move() },
      },
    }),
  ],
}))
Try: Drag a bar — the count updates as the total moves.

Restyling the parts

guide: true is shorthand for the parts at their defaults. Pass an object to switch and restyle each one.

A snap's stops draw as short ticks at the plot edge, where the axis also sits. Raise bounds.tickLength and bounds.tickOpacity to pull them clear of it.

bounds draws the constraint boundaries: a clamp's band and limits, a snap's stops, a maintainSum cap. On with guide: true.

catchment draws the radius in which a proximity pick resolves a free pointer to a mark. On with guide: true. Proximity picks that select a target (nearest, sweep, brush*) also turn catchment on when you omit guide — set guide: false to silence it.

track draws where a handle can travel, for handles whose range isn't a scale. Off by default — turn it on where that range isn't obvious from the mark, as on a face's parameters.

Each part takes color, dash, width and opacity; bounds adds bandOpacity, fontSize, tickLength and tickOpacity. A color on the guide itself sets all three parts at once. Theme tokens live at theme.guide.bounds|catchment|track (and theme.constraint.color).

One colour, or one per part

Left sets one colour for every part. Right styles each separately and lengthens the snap ticks.

// `guide: true` is shorthand for the parts at their defaults. Pass an object to
// switch and restyle each one.
const rows = [{ x: 30, y: 45 }, { x: 60, y: 62 }, { x: 84, y: 28 }];
const schema = {
  x: { type: "quantitative", domain: [0, 100] },
  y: { type: "quantitative", domain: [0, 100] },
};
const bounds = [
  clamp({ field: "y", min: 15, max: 80 }),
  snap({ field: "y", step: 10 }),
];

// One colour for every part.
mount(Elicit({
  width: 300, height: 220,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: rows, schema, constraints: bounds,
  marks: [
    point({
      size: 9,
      channels: {
        x: { field: "x" },
        y: { field: "y", edit: move({
          pick: "nearest", threshold: 40,
          guide: { bounds: true, catchment: true, color: "#0f766e" },
        }) },
      },
    }),
  ],
}));

// Or one per part. `snap` stops draw as short ticks at the plot edge, where the
// axis sits — `tickLength` and `tickOpacity` pull them clear of it.
mount(Elicit({
  width: 300, height: 220,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: rows, schema, constraints: bounds,
  marks: [
    point({
      size: 9,
      channels: {
        x: { field: "x" },
        y: { field: "y", edit: move({
          pick: "nearest", threshold: 40,
          guide: {
            bounds: {
              color: "#b91c1c", dash: "6 2", width: 1.5, opacity: 1,
              tickLength: 18, tickOpacity: 0.9,
            },
            catchment: { color: "#94a3b8", dash: "1 4", width: 1, opacity: 0.35 },
          },
        }) },
      },
    }),
  ],
}));
Try: Move near a dot to see the catchment ring, then drag it into the band.

Rule and region

Annotations you declare in guides: [...]. guides.region shades a band, guides.rule draws a reference line. Both position in data space through the same scales a mark uses, so they stay put as points move.

A target band with a rule

guides.region shades 40–60; guides.rule marks the midpoint.

mount(Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  guides: [
    guides.region({ y: [40, 60], fill: "#0d9488", opacity: 0.14 }),
    guides.rule({ y: 50, label: "target 50" }),
  ],
  data: [{ x: 20, y: 30 }, { x: 50, y: 55 }, { x: 80, y: 70 }],
  schema: {
    x: { type: "quantitative", domain: [0, 100] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    point({
      fill: "#0d9488",
      size: 9,
      channels: {
        x: { field: "x" },
        y: { field: "y" },
      },
      edits: [ move({ channels: ["x", "y"] }) ],
    }),
  ],
}))
Try: Drag a dot in and out of the target band.

Guides derived from the data

Every option takes a literal or a function of the guide context ({ data, scales, features, ui, width, height, stage }), so an annotation can read the rows it annotates. Here one rule is a fixed target and the other is the running mean. Guides rebuild each render, so it recomputes on every commit. The band tracks the spread the same way.

A mean line that chases the bars

guides.rule({ y: ({ data }) => d3.mean(data, (d) => d.y) }) reads the dataset.

mount(Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  guides: [
    // A literal: a fixed reference.
    guides.rule({ y: 50, label: "target 50" }),
    // A function of the context: recomputed from the live rows every render.
    guides.region({
      y: ({ data }) => [d3.min(data, (d) => d.y), d3.max(data, (d) => d.y)],
      fill: "#6366f1", opacity: 0.10,
    }),
    guides.rule({
      y: ({ data }) => d3.mean(data, (d) => d.y),
      label: "mean",
      stroke: "#e4572e",
    }),
  ],
  schema: {
    x: { type: "categorical",  domain: ["A", "B", "C", "D"] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  data: [
    { x: "A", y: 30 }, { x: "B", y: 55 },
    { x: "C", y: 45 }, { x: "D", y: 70 },
  ],
  constraints: [ clamp({ field: "y", min: 0, max: 100 }) ],
  marks: [
    bar({
      fill: "#6366f1",
      channels: {
        x: { field: "x" },
        y: { field: "y", edit: move() },
      },
    }),
  ],
}))
Try: Drag a bar. The fixed target holds; the mean line and the band follow.
