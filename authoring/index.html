Authoring SDK

Build new elicitation devices without forking the engine. Marks use authoring.encodeChannel / resolveStyle; edits use authoring.makeEdit + invertChannel; multi-event lifecycles register via authoring.registerDriver. Attach edits on a channel (y: { field, edit: move() }) or at mark level (edits: [...]) — never as a fake channels.edit key. For the model these extend, see Core concepts; for the stock catalogue, see Editing.

API reference

Mark SDK — elicit.plot

Shared foundation every mark factory uses. Import as authoring.encodeChannel (or the bare name in these docs). A mark never owns data or a domain — Elicit owns both.

authoring.normalizeMarkOptions(options) → options
authoring.encodeChannel(scales, channels, name, datum, fallback) → any
authoring.encodeAngle(scales, channels, datum, fallback?) → number
authoring.resolveStyle(scales, channels, datum, defaults?) → style
Options
OptionTypeDefaultDescription
build(data, scales, width, height)required—Emit FeatureNode[] (circle / rect / line / path / text). Resolve every position and style through encodeChannel / resolveStyle — never call scale(d[key]) by hand.
authoring.normalizeMarkOptionsfn—Call at the top of the factory. Desugars top-level shorthands (fill, size, …) into channels.*.value.
discreteScale'band' | 'point'—What the mark needs for discrete data (bar → band interval; point/line → tick). Leave unset for span-only marks (rule).
channels / edits / constraints / idpassthrough—Accept them on the factory and pass them through. Dropping edits or constraints silently disables interaction or invariants.

Returns / emits

A feature object the engine consumes. Line-family marks also set seriesKey, order, and supportsSeries: true.

Edit SDK — elicit.edit

Build descriptors and reuse the same invert/pick helpers the stock edits use. Prefer the ladder: stock edit → custom → makeEdit → registerDriver.

custom(fn, options) → Edit
invertChannel(ch, pointer, center?) → value
recenterSpan(node, chA, chB, pointer) → { a, b }
markCenter(node) → { x, y }
schemaDefaults(schema) → Datum
nearestMark(marks, x, y, threshold) → index | null
registerDriver({ name, onEvent, sessionKeys?, options?, wants?, selects? })
Options
OptionTypeDefaultDescription
makeEdit(spec)→ Edit—Normalize a partial spec into a full descriptor. Defaults: gesture: "drag", pick: "direct", channels: null (inject the channel it’s placed on). Keys the descriptor doesn’t know pass through onto the edit — the sanctioned way a custom driver carries per-edit options (the built-ins’ edgeInset works the same way).
apply(ctx)fn—Pure given ctx. Return a datum (splice at index), a full array (whole-dataset rewrite), or undefined (no-op). Never mutate ctx.data.

Descriptors the engine routes. Multi-event lifecycles belong in a driver, not an if (pick === …) branch in the engine.

Drivers — authoring.registerDriver

A driver owns a multi-event plane lifecycle (hover / drag / click, …). Built-ins cover nearest, sweep, draw, brush, probe, plane, …. Register a new one when stock pick values aren’t enough.

registerDriver({ name, onEvent(ctx), sessionKeys?, options?, wants?(edit), selects? })
Options
OptionTypeDefaultDescription
wants(edit)→ boolean—Claim edits — usually edit.pick === name.
onEvent(ctx)→ boolean—Return whether anything changed (commit or redraw). ctx has event, edits, marks, session, preview, runEdit, previewEdit.
runEdit / previewEdit(edit, index) → boolean—Commit through constraints + undo, or park an uncommitted hover preview.
selectsbooleanfalseIf true, the driver writes a selection into session so guide: true can draw the snap ring / highlight.
Returns / emits

Replaces a built-in of the same name, or adds a new pick. No engine fork required.

A custom mark

A mark is a view over the chart’s one dataset. The factory returns a feature object; the only required method is build(data, scales, width, height). Call normalizeMarkOptions first, resolve every channel through encodeChannel / resolveStyle, spread authoring.markCommon(opts) to pass id / edits / constraints / table through verbatim, and set discreteScale when discrete data needs a band or a point. Don’t set mark-wide pointerEvents — leave that to the engine. To let a datum’s derived channels ({ fn }) see their row index and the dataset, pass the optional index and data args when you resolve per datum: authoring.resolveStyle(scales, channels, d, defaults, i, data).

A custom square mark

authoring.normalizeMarkOptions → encodeChannel / resolveStyle → FeatureNode[]. Stock drag still works because the nodes carry data and index.

// A minimal mark factory — same contract as point/bar.
function square(options = {}) {
  const opts = authoring.normalizeMarkOptions(options, { mark: "square", allow: [] });
  const { channels = {} } = opts;
  return {
    // id / edits / constraints / table, passed through verbatim.
    ...authoring.markCommon(opts),
    type: "square",
    channels,
    discreteScale: "point",
    xKey: channels.x && channels.x.field,
    yKey: channels.y && channels.y.field,
    build(data, scales, width, height) {
      return data.map((d, i) => {
        const style = authoring.resolveStyle(scales, channels, d, { fill: "#4f46e5" });
        const cx = authoring.encodeChannel(scales, channels, "x", d, width / 2);
        const cy = authoring.encodeChannel(scales, channels, "y", d, height / 2);
        const r = authoring.encodeChannel(scales, channels, "size", d, 8);
        const side = Math.max(0, r * 2);
        return {
          type: "rect",
          x: cx - side / 2, y: cy - side / 2,
          width: side, height: side,
          ...style, data: d, index: i,
        };
      });
    },
  };
}

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: [{ x: 25, y: 40 }, { x: 55, y: 70 }, { x: 80, y: 35 }],
  schema: {
    x: { type: "quantitative", domain: [0, 100] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    square({
      size: 9, stroke: "#1f2733", strokeWidth: 1,
      channels: {
        x: { field: "x" },
        y: { field: "y" },
      },
      edits: [ move({ channels: ["x", "y"] }) ],
    }),
  ],
}))
Try: Drag a square — same edit path as a point.

The edit ladder

Reach for the smallest tool that fits:

  1. Stock edit — move, resize, create, … when the behaviour already exists.
  2. custom(fn) — one-off apply, same gesture/pick defaults.
  3. makeEdit(spec) — full descriptor control (type, pick, cardinality, name, …).
  4. registerDriver — multi-event lifecycle / a new pick value.

apply is pure: return a new datum, a new array, or undefined. Prefer invertChannel over hand-rolled scale.invert.

custom(fn) — a one-off apply

custom wraps fn as apply. Drag rewrites y from the pointer; x still uses stock move().

// Level B — custom(fn): one-off apply, stock gesture/pick defaults.
const bumpY = custom((ctx) => {
  if (!ctx.datum) return undefined;
  const y = ctx.scales.y.invertValue(ctx.pointer.y);
  return { ...ctx.datum, y: Math.round(y) };
});

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: [{ x: 30, y: 40 }, { x: 70, y: 65 }],
  schema: {
    x: { type: "quantitative", domain: [0, 100] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    point({
      fill: "#0d9488", size: 9, stroke: "#1f2733", strokeWidth: 1,
      channels: {
        x: { field: "x", edit: move() },
        y: { field: "y" },
      },
      edits: [ bumpY ],
    }),
  ],
}))
Try: Drag vertically on a dot to set y; drag the dot itself to move in x.

makeEdit + invertChannel

Full descriptor: invert y, then snap to the nearest 10. Same idea as custom, with an explicit type and channels list.

const snapDrag = authoring.makeEdit({
  type: "snapDrag",
  gesture: "drag",
  channels: ["y"],
  apply: (ctx) => {
    const ch = ctx.channels[0];
    const v = authoring.invertChannel(ch, ctx.pointer);
    if (v === undefined || !ctx.datum) return undefined;
    return { ...ctx.datum, [ch.field]: Math.round(v / 10) * 10 };
  },
});
mount(Elicit({
  width: 360, height: 240,
  margins: { top: 16, right: 16, bottom: 28, left: 34 },
  data: [ { cat: "A", n: 40 } ],
  schema: {
    cat: { type: "categorical", domain: ["A"] },
    n: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    point({
      fill: "#2563eb", size: 10,
      channels: { x: { field: "cat" }, y: { field: "n" } },
      edits: [ snapDrag ],
    }),
  ],
}));
Try: Drag the point — it lands on multiples of 10.

When apply returns a full array

Most edits return one datum and the engine splices it at index. Whole-dataset edits return a new array — reorder, create, remove. rank() is the built-in example: drag swaps discrete rank slots.

rank() — array-returning apply

Point scale over ranks; drag swaps with the nearest slot. Your makeEdit can return [...ctx.data] the same way.

mount(Elicit({
  width: 360, height: 260,

  data: [
    { item: "A", rank: 1 },
    { item: "B", rank: 2 },
    { item: "C", rank: 3 },
  ],
  schema: {
    item: { type: "categorical", domain: ["A", "B", "C"] },
    rank: { type: "ordinal", domain: [1, 2, 3] },
  },
  marks: [
    point({
      fill: "#0d9488", size: 9,
      channels: {
        x: { value: 40 },
        y: { field: "rank", edit: rank() },

    text({
      fontSize: 13,
      channels: {
        x: { value: 56 },
        y: { field: "rank" },
        text: { field: "item" },
        textAnchor: { value: "start" },

  ],

Register a driver

Stock pick values (direct, nearest, plane, probe, sweep, …) already cover most lifecycles. When you need a new one, register a driver. An edit reaches it by naming it — pick: "clickNearest" — and every edit reaches exactly one driver; wants(edit) is only for claiming an edit by capability (a relative slide) and never re-tests pick. onEvent owns hover/click/drag, and runEdit / previewEdit commit or preview through the same constraint and undo path. Declare sessionKeys: the per-feature session is shared with every other driver on the mark, and the session.clear() you are handed nulls exactly those keys. Declare options for any knob your driver reads off the edit, or the engine reports it as an unknown option. Set selects: true if guide: true should draw a snap ring.

clickNearest — hover, then click to bump

registerDriver + makeEdit({ pick: "clickNearest" }). Hover highlights; click adds 10 to y.

// A tiny driver: hover highlights the nearest mark; click bumps its y.
authoring.registerDriver({
  name: "clickNearest",
  // The keys this driver owns in the shared per-feature session; clear() nulls them.
  sessionKeys: ["px", "py", "threshold", "hoverIndex"],
  selects: true,
  onEvent({ event, edits, marks, session, runEdit }) {
    const threshold = 48;
    if (event.type === "hover") {
      session.set({
        px: event.x, py: event.y, threshold,
        hoverIndex: authoring.nearestMark(marks, event.x, event.y, threshold),
      });
      return true;
    }
    if (event.type === "hoverout") {
      session.clear();
      return true;
    }
    if (event.type === "click") {
      const index = authoring.nearestMark(marks, event.x, event.y, threshold);
      if (index == null) return false;
      let changed = false;
      for (const e of edits) {
        if (e.gesture === "click" && runEdit(e, index)) changed = true;
      }
      return changed;
    }
    return false;
  },
});

const bump = authoring.makeEdit({
  type: "bump",
  pick: "clickNearest",
  gesture: "click",
  channels: ["y"],
  guide: true,
  apply: (ctx) => {
    if (!ctx.datum) return undefined;
    const field = ctx.channels[0].field;
    return { ...ctx.datum, [field]: Math.min(100, (ctx.datum[field] || 0) + 10) };
  },
});

mount(Elicit({
  width: 380, height: 240,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: [{ x: 25, y: 30 }, { x: 55, y: 55 }, { x: 80, y: 40 }],
  schema: {
    x: { type: "quantitative", domain: [0, 100] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    point({
      fill: "#4f46e5", size: 9, stroke: "#1f2733", strokeWidth: 1,
      channels: {
        x: { field: "x" },
        y: { field: "y" },
      },
      edits: [ bump ],
    }),
  ],
}))

Glyphs: prefer a group of marks

If a glyph’s handles map to distinct fields of a row, build it as a composite — ordinary marks over the same rows — so direct-pick dispatch keeps one handle from touching another. Only when several handles must live on one feature over one datum (positions are derived, not fields) do you need node.channel plus a when guard. Reach for that last.

A whole-dataset plane gesture (create, rotate, …) belongs on exactly one mark — two marks with the same plane edit would fire twice per click.

Helpers to reuse

Don’t reinvent proximity or minting:

  • invertChannel / recenterSpan / markCenter — pointer ↔ data for positional edits
  • schemaDefaults(schema) — mint a row with every field set to its default (or null)
  • authoring.nextSeriesKey(data, seriesField) — next free series id for a new line
  • nearestMark / nearestSeries / nearestMarkOnAxis — shared distance pickers

For create-like customs, set cardinality: "append" so constraints know which row is new; for an edit that runs the pointer back through a scale, set inverts: true so the dead-drag guard can check the channel. A custom mark stamps type: "square" — the one identity key every feature kind carries. For external UI, give the edit a name and drive it with el.control(name).
