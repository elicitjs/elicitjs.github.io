Theming & style

Every default colour, font, and affordance token lives in one place — the theme. Pass a partial theme on Elicit (or on any widget) and it deep-merges over the built-in defaults, so you name only what you change. It sits alongside, and under, the two style hooks you already have: a per-datum paint channel (fill, stroke) still wins over any theme token, and the effects layer still owns interaction feedback. The showcase is the survey widgets: one theme restyles the whole family.

API reference

theme (on Elicit)

The style layer, passed as theme on Elicit (or on any widget). A partial, deep-merged over the built-in DEFAULT_THEME — you name only the tokens you change. Precedence, most specific first: a per-datum channel/option > theme.marks[name] > the theme token > the renderer default.

theme: { ink, accent, muted, handle, handleStroke, background, palette, ramp, diverging,
         font, axis, grid, guide, constraint, effects, ghost, widget, marks }
Options
OptionTypeDefaultDescription
inkstringsteelblueThe primary mark colour — every mark that has no explicit paint channel reads it (bar, point, line, area, rect, …).
accentstring#2563ebInteractive emphasis: draggable handles, a committed survey answer, an editable-axis handle.
mutedstring#9ca3afSecondary ink — a de-emphasised mark, a supporting label.
handle / handleStrokestring#2563eb / #fffFill and rim of every grip a mark draws. A mark’s own handleColor still wins.
backgroundstring | nullnullThe chart backdrop, applied as the svg/canvas CSS background (margin band included). null is transparent (the host page shows through); set it for a self-contained dark-mode chart — see themes.dark.
palette / ramp / divergingstring[]Tableau10 · blues · RdBuColour-scale defaults for a fill/stroke channel that names no explicit range or scheme.
font{ family, size, labelSize, titleSize }family: nullTypography. A non-null family is emitted on the root svg (and used by the canvas renderer) so every label inherits it; the default null inherits the host page's font.
axis / grid / guideobjectneutral greysChart chrome tokens — axis spine/labels/handle, grid lines, and the reference-rule / region / legend guides.
constraint{ color }#e4572eThe colour an edit’s guide draws its bounds, catchment and track in.
effectsobjectoutline + dimTheme-level defaults for the effects layer. A chart’s own effects option layers over it.
ghost{ opacity, fill, stroke, strokeDasharray }opacity: 0.45How a probe preview is dimmed: a ghost multiplies its opacity by this, and a non-null fill/stroke/dash overrides the committed paint.

marksRecord<mark, style>{}Sparse per-mark default overrides, keyed by mark name — e.g. { bar: { fill: "crimson" } }.

themes

The built-in themes. themes.default is the library look; themes.survey is a clean, professional survey style; themes.dark is a self-contained dark mode (it sets background). Each is a partial — pass it as theme, or layer your own on top with a deep-merge.

themes.default
themes.survey
themes.dark

setTheme(partial)

Set the application-wide default theme. Every chart created afterwards inherits it unless it passes its own theme, which layers on top. Pass null to reset.

setTheme(themes.survey)
setTheme({ ink: '#4f46e5' })
setTheme(null)

A themed instrument

themes.survey is a built-in professional look. Pass it to any widget and the answer ink, the chrome, and the affordance rings/track/labels all follow it — the behaviour is unchanged, only the style.

The survey theme

One object — themes.survey — restyles ink, chrome, and every affordance.

// One object restyles the whole instrument: answer ink, chrome, and the
// affordance rings/track/labels all follow themes.survey.
mount(Elicit(widgets.likert({
  question: "How satisfied are you with the result?",
  options: ["Very low", "Low", "Neutral", "High", "Very high"],
  theme: themes.survey,
})));
Try: move across the options, click to answer — the look is the only change.

Dark mode

Yes — a theme can produce a fully dark chart. The background token paints the chart's own surface (svg / canvas, margin band included), so themes.dark is self-contained: light ink, light labels, a slate grid, no host CSS required. The same spec renders light or dark; only the theme changes.

themes.dark

A slate backdrop with light ink and chrome — the chart paints its own surface.

// themes.dark carries a `background` token, so the chart paints its own dark
// surface — light ink, light labels, slate grid, no host CSS required. The same
// spec renders identically light or dark; only the theme changes.
mount(Elicit({
  width: 440, height: 240,
  margins: { top: 20, right: 20, bottom: 30, left: 36 },
  data: [{ cat: "A", n: 30 }, { cat: "B", n: 55 }, { cat: "C", n: 40 }, { cat: "D", n: 22 }],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n: { type: "quantitative", domain: [0, 60] },
  },
  theme: themes.dark,
  axes: { x: {}, y: { grid: true } },
  marks: [
    barY({ channels: { x: { field: "cat" }, y: { field: "n", edit: move() } } }),
  ],
}));
Try: drag a bar — the interaction is identical, only the palette is dark.

A theme on a plain chart

A theme is plain data — no functions, no classes — so it merges cleanly. ink is the primary mark colour (every mark with no explicit paint channel reads it); axis and grid are the chrome. Name a token and it changes; leave one out and it inherits the default.

Per-chart theme

ink recolours the bars; axis/grid restyle the chrome. Drag a bar — the value axis still works.

// A theme on a plain chart. `ink` recolours every mark that has no explicit
// paint channel; `axis`/`grid` restyle the chrome. A partial — you name only
// the tokens you change, the rest inherit the default.
mount(Elicit({
  width: 440, height: 240,
  margins: { top: 20, right: 20, bottom: 30, left: 36 },
  data: [{ cat: "A", n: 30 }, { cat: "B", n: 55 }, { cat: "C", n: 40 }, { cat: "D", n: 22 }],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n: { type: "quantitative", domain: [0, 60] },
  },
  theme: {
    ink: "#e11d48",
    axis: { stroke: "#cbd5e1", labelFill: "#64748b" },
    grid: { stroke: "#f1f5f9" },
  },
  axes: { x: {}, y: { grid: true } },
  marks: [
    barY({ channels: { x: { field: "cat" }, y: { field: "n", edit: move() } } }),
  ],
}));
Try: drag a bar up or down.

Overrides & precedence

Resolution is layered, most specific first: a per-datum channel or option beats theme.marks[name], which beats the theme token (ink), which beats the renderer default. So a theme sets the family look while a single mark can still opt out.

Per-mark override

ink colours the bars; theme.marks.point overrides just the dots.

// Precedence, most specific first: a per-datum channel > theme.marks[name] >
// the theme token > the renderer default. Here `ink` colours the bars, but
// theme.marks.point overrides just the dots — and a channel would still win.
mount(Elicit({
  width: 440, height: 240,
  margins: { top: 20, right: 20, bottom: 30, left: 36 },
  data: [{ cat: "A", n: 30 }, { cat: "B", n: 55 }, { cat: "C", n: 40 }, { cat: "D", n: 22 }],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C", "D"] },
    n: { type: "quantitative", domain: [0, 60] },
  },
  theme: {
    ink: "#0ea5e9",
    marks: { point: { fill: "#f59e0b" } },
  },
  marks: [
    barY({ channels: { x: { field: "cat" }, y: { field: "n" } } }),
    point({
      size: 6,
      channels: { x: { field: "cat" }, y: { field: "n", edit: move() } },
    }),
  ],
}));
Try: drag a dot — its colour comes from theme.marks.point, not ink.

App-wide defaults

To theme a whole application without threading theme through every chart, call setTheme(partial) once at startup — every chart built afterwards inherits it, and a chart's own theme still layers on top. setTheme(themes.survey) makes the survey look the default; setTheme(null) resets to the built-in.

import { setTheme, themes } from "elicit-js";

setTheme(themes.survey);          // app-wide default
// …every Elicit(...) after this inherits it
setTheme({ ink: "#4f46e5" });     // or just a token or two
