Selection

Which rows are currently picked. Selection is pipeline state, not a column: edit.select() makes a mark selectable, the selected rows get the selected effect, and an edit that needs a row to write to — a legend picker, an external control — reads the selection instead of guessing. Nothing about it touches the elicited data.

API reference

edit.select

Makes a mark selectable. Selection is transient pipeline state — the chart remembers which rows are picked, and nothing is written to the data. That is the point: it replaces a selected column, so no change fires, nothing lands in undo, and the elicited dataset stays clean.

edit.select({ multi, exclusive, toggle }) → Edit
Options
OptionTypeDefaultDescription
multibooleanfalseShift- or meta-click adds to the selection; a plain click still replaces it. Shift-clicking a selected row removes it. Turning this on changes nothing about the gesture you already had.
exclusivebooleantrueSelecting a row clears the rest. false makes every click additive, with no modifier — the flat override for a chart that is always multi.
togglebooleantrueClicking an already-selected row deselects it. false never deselects.

Selection API

Selection has its own small API beside getData/setData, and its own select event. Every route — a mark click, an external control, the keyboard — goes through the same commit, so the selection is always in one shape. Indices are rows of the primary table.

el.getSelection() → number | null      ·   el.getSelectionAll() → number[]
el.select(i | number[] | null) → boolean
el.toggleSelection(i) → boolean        ·   el.selectAll() → boolean
el.selectWhere(field, value, { all }) → boolean
el.clearSelection() → boolean          ·   el.on('select', (first, all) => …)
Options
OptionTypeDefaultDescription
getSelection / getSelectionAll() => number | null / number[]—The first selected row, and every selected row. getSelection stays scalar when several are selected, so code written against a single selection keeps working. A stale index (its row was removed) reads as null.
select(index | number[] | null)—Replace the selection. An array selects exactly those rows in one commit; null, an empty array, or an out-of-range index clears.
toggleSelection / selectAll(index) / ()—Add or remove one row, leaving the rest alone (the external counterpart of a shift-click); or take every row.
selectWhere(field | predicate, value?, { all }?)all: falseSelect by category or predicate. The default takes the first match; { all: true } takes every one, which is what selecting a category usually means.
clearSelection()—Empty the selection. The same commit path, so the select event fires.
on('select')(first, all) => void—Fires whenever the selection moves. No data changed, so this is not a change event.

State, not data

A selected column would be answers mixed with interface state: it would show up in getData(), fire change, and land in undo. So selection lives beside the data instead. It survives edits, resets when you call setData or advance a stage, and reports through its own select event.

edit.select() is a direct-pick click. A plain click selects one row and clears the rest; clicking the selected row again deselects it.

Click a bar to select it

The selected bar takes the highlight outline. getData() gains no column.

mount(Elicit({
  width: 380, height: 210,
  margins: { top: 20, right: 16, bottom: 30, left: 40 },
  data: [
    { name: "A", value: 12 },
    { name: "B", value: 8  },
    { name: "C", value: 15 },
    { name: "D", value: 6  },
  ],
  schema: {
    name:  { type: "categorical", domain: ["A", "B", "C", "D"] },
    value: { type: "quantitative", domain: [0, 16] },
  },
  marks: [
    barY({
      fill: "#4f46e5",
      channels: { x: { field: "name" }, y: { field: "value", edit: move() } },
      edits: [ edit.select() ]
    }),
  ],
}))
Try: Click a bar to select it, click it again to deselect · drag the top to change its value.

Seeing the selection

Selected rows get the selected effect — an orange outline by default, on every mark over that row, so selecting a bar also outlines its label. Restyle it on the spec:

effects: { selected: { outline: { color: "#2563eb", width: 3 } } }

Selection outranks hovered and is outranked by grabbed, so a row you are dragging reads as grabbed rather than merely selected.

Selecting several rows

edit.select({ multi: true }) makes shift-click (or meta-click) add to the selection; shift-clicking a selected row takes it back out. A plain click still replaces the whole selection, so the gesture you already had is unchanged. Use exclusive: false for a chart where every click should be additive with no modifier.

An edit that writes "the selected row" writes all of them, so one legend swatch click recategorises the whole selection.

Shift-click to build a selection

One swatch click sets the group on every selected bar.

mount(Elicit({
  width: 380, height: 210,
  margins: { top: 20, right: 16, bottom: 30, left: 40 },
  data: [
    { name: "A", value: 12, group: "North" },
    { name: "B", value: 8,  group: "South" },
    { name: "C", value: 15, group: "East"  },
    { name: "D", value: 6,  group: "West"  },
  ],
  schema: {
    name:  { type: "categorical", domain: ["A", "B", "C", "D"] },
    group: { type: "categorical", domain: ["North", "South", "East", "West"] },
    value: { type: "quantitative", domain: [0, 16] },
  },
  marks: [
    barY({
      channels: {
        x: { field: "name" },
        y: { field: "value" },
        fill: { field: "group", edit: edit.legend.category() },
      },
      edits: [ edit.select({ multi: true }) ]
    }),
  ],
}))
Try: Click a bar, shift-click another, then click a legend swatch.

Driving it from outside

The same commit backs every route, so an external control and a click leave the selection in one shape. See External controls for the surrounding API.

el.select(2);                                 // replace with row 2
el.select([0, 2]);                            // replace with rows 0 and 2
el.toggleSelection(3);                        // add or remove row 3
el.selectAll();
el.selectWhere("group", "North", { all: true });   // a whole category
el.clearSelection();

el.getSelection();                            // 0  (the first, or null)
el.getSelectionAll();                         // [0, 2]
el.on("select", (first, all) => …);

selectWhere takes the first match by default. Pass { all: true } for every row of a category — the usual meaning when a control names a value rather than a row.

Edits that read the selection

A gesture that carries no row of its own has to get one from somewhere, and the selection is it. A legend picker is the main case: a swatch names a value, so its row defaults to the selection.

The swatch the selection currently holds is ringed. With nothing selected and more than one row, a picker has no target and no ring. A one-row table needs no selection — one row is unambiguous. If nothing in the chart can ever select, the picker is decoration, and a warning says so.
